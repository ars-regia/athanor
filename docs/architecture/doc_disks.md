# Athanor disk utility

Status: **revision 2, approved by the maintainer on 2026-10-08 with the recommendations of review batch 2 (ADR-0095). Revision 1 (draft, 2026-10-05) applied the maintainer's decisions of that day; amended on 2026-10-06 by maintainer decision A2-14 (#159): Athanor does not build its own disk utility; GNOME Disks is the disk utility. Kept as decided: the polkit rule (DK20 A) and the USBGuard path (DK20 D, DK21). Decided on 2026-10-08 (review batch 2, decisions 12 to 18): the shared `udisks` module (DK3) and the `usbguard` module are kept and built, the `noexec` default (DK20 B) is decided (ADR-0025), and the `udisksd` drop-in (DK20 C) is kept after spike S5. Section 7 records the amendment and overrides the text above where they disagree.** It is the specification that `doc_software.md` revision 3, decision 7, calls for: Athanor's own disk utility over `udisks2`, with its acceptance cases for destructive operations. It designs the program, what it shows, the operations of its first release, what it must refuse on the running system's disk, the confirmations that guard data, the handling of passphrases, the interfaces it offers to the file manager and the control center, its confinement, its tests and the order of construction. The maintainer's decisions of 2026-10-05 are recorded in section 6. Three of them change the system rather than the program (the polkit rule on removable drives, the default mount options, the hardening of `udisksd`); they are built as steps of their own (DK20).

- **What udisks 2.11.2 does, read in its source** (tag `udisks-2.11.2`, `github.com/storaged-project/udisks`, 2026-10-05).
  - Formatting asks `modify-device`, or `modify-device-system` when the block has `HintSystem`, or `modify-device-other-seat`; passing `mkfs-args` always asks `modify-device-system`; `tear-down` or `config-items` also ask `modify-system-configuration` (`src/udiskslinuxblock.c:2926-2955`). The same three actions guard partition creation, deletion and every partition property (`udiskslinuxpartitiontable.c:332-348`, `udiskslinuxpartition.c:142-158`).
  - Formatting first wipes signatures with `bd_fs_clean (device, FALSE)` (`udiskslinuxblock.c:3092-3104`), which opens the device with `O_EXCL` unless forced (`libblockdev` 3.4.0, `src/plugins/fs/generic.c:385-412`), so a block whose filesystem is mounted, or which a LUKS mapping holds, is refused as busy. `dry-run-first` runs after that wipe (`udiskslinuxblock.c:3535-3586`), so it does not protect the old data.
  - `OpenForBackup` and `OpenForRestore` open the device `O_EXCL`, read-only and write-only; `OpenDevice` takes a mode (`r`, `w`, `rw`) and extra flags; all four ask `open-device`, or `open-device-system` with `HintSystem` (`udiskslinuxblock.c:3905-3925`, `3976-3997`, `4050-4073`, `4133-4160`, `open_device`). A grant for reading a device is therefore also a grant for writing it, for as long as the grant is kept.
  - Mounts made by udisks always carry `nodev,nosuid` (`udiskslinuxfilesystem.c:1154`), never `noexec`; the default allow list admits `exec`, `noexec`, `ro` and `rw` (`/etc/udisks2/mount_options.conf.example`).
  - `/etc/udisks2/mount_options.conf` selects options either for every filesystem (`[defaults]`, key `defaults`) or for one block device named by its path or a `/dev/disk/by-*` link, matched exactly (`src/udiskslinuxmountoptions.c:179-205`, `226-268`); there is no selector for removable drives. The configured defaults are placed first and the caller's options after them (`prepend_default_mount_options`, `udiskslinuxmountoptions.c:998-1110`), so a caller's `exec` follows a default `noexec`.
  - Unlocking handles LUKS, BitLocker and TCRYPT volumes (`udiskslinuxencrypted.c:389-396`).
  - Every polkit check carries details: `drive` (vendor, model and device path), `drive.serial`, `drive.model`, `drive.removable`, `id.label`, `id.uuid` and the message, such as "Authentication is required to format $(drive)" (`src/udisksdaemonutil.c:797-905`). A polkit rule can see which disk a request is about.
- **The polkit actions and Athanor's rules.** `org.freedesktop.UDisks2.policy` declares 52 actions. The ones this document uses, with their defaults for an active local session: `filesystem-mount`, `encrypted-unlock`, `encrypted-change-passphrase`, `loop-setup`, `power-off-drive`, `eject-media`, `modify-device`, `ata-smart-update`, `nvme-smart-update`, `cancel-job` are `yes`; `filesystem-mount-system`, `filesystem-unmount-others`, `encrypted-unlock-system`, `encrypted-lock-others`, `encrypted-change-passphrase-system`, `modify-device-system`, `open-device`, `open-device-system`, `ata-smart-selftest`, `nvme-smart-selftest`, `manage-swapspace` are `auth_admin_keep`; `modify-system-configuration` is `auth_admin`. Inactive and remote sessions get `auth_admin` for all of them. Administrators are `wheel` (`/usr/share/polkit-1/rules.d/50-default.rules`). Until 2026-10-07 Athanor shipped one rule that touched udisks, an `addRule` in `forge/specs/athanor-system-tweaks/SOURCES/etc/polkit-1/rules.d/10-athanor-wheel-admin.rules`: for `filesystem-mount` and `eject-media` it returned `YES` for any member of `wheel`, whatever the session, and `AUTH_ADMIN` for anyone else. So a user outside `wheel` typed an administrator's password to mount or eject a USB stick, yet formatted it with no password (`modify-device` is untouched), and a member of `wheel` mounted from an SSH session with no password. Decision 5 removed that `addRule` and returned to udisks's defaults (DK20 A, `athanor-system-tweaks` 1.0.0-8).
- **The session's polkit agent** is cosmic-osd until it retires in one step together with `athanor-osd`, Athanor's own polkit agent and the end-of-session dialogs (`doc_lock_and_prompts.md` decision D7, `doc_osd.md` decision M4, ruled 2026-10-05). Every `auth_admin` request of this utility is answered there.

The Fedora 43 repository carries `usbguard-dbus-1.1.4-1.fc43`, which requires `usbguard = 1.1.4`, `polkit` and `libusbguard.so.1` (`dnf repoquery --releasever=43`, 2026-10-05). ## 2. Decisions

**DK1. One program, one crate, libadwaita. (withdrawn, section 7)** `athanor-disks` in `forge/specs/athanor-disks`, application id `os.athanor.Disks`, a GTK4 application on `libadwaita` 0.9.2 (crates.io, which requires `gtk4 ^0.11`, the workspace's `0.11.4`), packaged as a custom RPM.

- **One process.** The window does every step itself on the D-Bus thread of DK3; it starts no helper and no child process. Long work that udisks runs (formatting, checking) is a job in `udisksd`; the only long work in the process is the copy of DK14.
- **Logic without GTK types,** as SH4 and BR1 ask: the classification of DK5, the confirmation text of DK7, the sequences of DK8 and DK12 and the copy of DK14 are modules with no GTK type, tested without a display.
- **Following the system:** libadwaita takes the colour scheme, the accent and the contrast from the Settings portal; nothing is forced by CSS. Strings through gettext from the first commit, English and Italian.
- **Replaces GNOME Disks** at the last step of DK19, and with it the two MIME handlers above (DK14).

**DK2. Every change goes through udisks2; the program holds no privilege. (withdrawn as the design of a program, section 7)** No setuid helper, no root process, no unit of its own, no direct `ioctl` on a disk it has not received from udisks. Each operation is one udisks method under udisks's own polkit action:

| Operation                                                             | udisks method                                                                                                            | Polkit action: removable drive / internal drive                                                      |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| Mount, unmount                                                        | `Filesystem.Mount`, `Unmount`                                                                                            | `filesystem-mount` / `filesystem-mount-system`; `filesystem-unmount-others` for another user's mount |
| Unlock, lock                                                          | `Encrypted.Unlock`, `Lock`                                                                                               | `encrypted-unlock` / `encrypted-unlock-system`; `encrypted-lock-others`                              |
| Change passphrase                                                     | `Encrypted.ChangePassphrase`                                                                                             | `encrypted-change-passphrase` / `-system`                                                            |
| Format a drive or a volume, create or delete a partition, set a label | `Block.Format`, `PartitionTable.CreatePartitionAndFormat`, `Partition.Delete`, `Filesystem.SetLabel`                     | `modify-device` / `modify-device-system`                                                             |
| Check, repair                                                         | `Filesystem.Check`, `Repair`                                                                                             | `modify-device` / `modify-device-system`                                                             |
| Safely remove                                                         | `Drive.PowerOff`, or `Drive.Eject` for media                                                                             | `power-off-drive`, `eject-media` / their `-system` forms                                             |
| Write an image, verify it                                             | `Block.OpenDevice` (`rw`, `O_EXCL`, `O_DIRECT`)                                                                          | `open-device` / `open-device-system`                                                                 |
| Attach an image                                                       | `Manager.LoopSetup` (`read-only`)                                                                                        | `loop-setup`                                                                                         |
| Mount at startup, and stop it                                         | `Block.AddConfigurationItem`, `RemoveConfigurationItem` (`fstab` only)                                                   | `modify-system-configuration` (`auth_admin`, every time)                                             |
| Health, self-test                                                     | `Drive.Ata.SmartUpdate`, `SmartSelftestStart`; `NVMe.Controller.SmartUpdate`, `SmartGetAttributes`, `SmartSelftestStart` | `ata-smart-update`, `nvme-smart-update`; `ata-smart-selftest`, `nvme-smart-selftest`                 |

- **Never passed:** `mkfs-args`, `tear-down`, `config-items`, `force` on unmount; never called: `Format` with `erase` set to `ata-secure-erase*`, `NVMe.Controller.SanitizeStart`, `NVMe.Namespace.FormatNamespace`, `Drive.SetConfiguration`, `Manager.MDRaidCreate`, `Block.OpenForBenchmark` (no benchmark, decision 2). `Block.AddConfigurationItem` and `RemoveConfigurationItem` are called only for the `fstab` entry of DK12, never for `crypttab`.
- **The program ships no polkit rule.** The udisks part of Athanor's rule is removed by a system change of its own (DK20, decision 5), after which udisks's defaults apply. The refusal of DK6 stays a safeguard inside this program, not a polkit boundary (decision 7). `system/athanor-bus-api/src/polkit.rs` is not involved: the utility is a client of udisks, which does its own polkit checks.

**DK3. udisks through `zbus`, in the shared models crate.** The utility's model of drives and blocks is one module, `udisks`, of `system/athanor-services` (CC2): typed proxies declared once, run on the Tokio thread of CC3, publishing state on `watch` channels and taking commands on `mpsc`.

- **Shared, not duplicated.** This document owns the module; the control center's Devices page (CC5, CC8) and the file manager (`doc_files.md` FM14) use it for mount, unmount, unlock, lock and safe removal, and neither keeps a udisks model of its own (ruled 2026-10-05). It holds the sequences of DK8 and DK12. The destructive operations (DK10, DK14) stay in `athanor-disks`. (Amended 2026-10-06, section 7: `athanor-disks` is withdrawn, and with it DK10, DK14 and DK19, which scheduled this module; the destructive operations are GNOME Disks's own, through udisks. DK3 is kept and built (ADR-0007, decision 12) as one change of `system/athanor-services`, together with the `usbguard` module of DK21, before steps 4 and 5 of SD22 in `doc_session_daemons.md`; its owner is the maintenance owner of SH3, whom the maintainer names.)
- **The proxies** are declared with `#[proxy]` in the module, generated once with `zbus-xmlgen` from the introspection data of udisks 2.11.2 and checked in, as CC3 does for every service (decision 9). The `udisks2` crate is not used.
- **Udisks's own objects are the source of truth.** The model subscribes to `ObjectManager` signals and to `PropertiesChanged`; it never caches a decision across a change of the objects it was based on (DK9).

**DK4. What the window shows. (withdrawn, section 7)**

- **A sidebar of drives**, in three groups: "This computer" (internal drives, the system disk first and marked "System disk"), "Removable" (USB, memory cards, optical), "Disk images" (loop devices this user attached, `Loop.SetupByUID`). Hidden: `zram` devices, the dm-verity data and hash devices of `/usr` and any other device-mapper target that is not a LUKS cleartext device, loop devices set up by others.
- **A drive page:** model, capacity in decimal units with the exact byte count in the accessible description, serial number, connection (`ConnectionBus`), health summary (DK13), and a map of its partitions and free space as a bar of segments; each segment is a button, reached with Tab and the arrow keys, named by number, label, type, size and state ("Partition 2, Data, ext4, 500 GB, mounted at /run/media/ada/Data").
- **A volume page** under the map: type, label, UUID, size and used space when udisks reports it, mount points, the LUKS state with its cleartext volume beneath, and the actions DK10 to DK12 allow for that class (DK5).
- **A blocked USB storage device** is listed in the sidebar group "Removable" only as a row "Blocked" (DK21), with its name, serial, size when the descriptor gives one, and an "Allow" button. It has no page, no map and no volume action, because the kernel has made no block device for it. The row appears and goes away with the `DevicePresenceChanged` signal.
- **Untrusted text.** A device chooses its own model, serial, partition names and filesystem labels. Every such string is set as plain text, never markup, truncated, and stripped of control and bidirectional characters, as SH12 states; a label that changes under that cleaning is shown with a note "Label contains hidden characters". Two connected drives with the same model and serial are told apart by their size and device path, both shown.

**DK5. Every target belongs to one class. (withdrawn, section 7)** The class of the drive decides what DK6 and DK7 allow. It is computed by the utility from udisks's objects and the kernel's view, never from a list written into the code, and it is the same whichever option of D6 the image uses.

| Class                               | Definition                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S, system**                       | a drive that holds a system device, as defined below                                                                                                                                                                                                                                                                                                       |
| **O, internal with another system** | not S, `HintSystem=true`, and a partition whose type GUID is the ESP (`c12a7328-f81f-11d2-ba4b-00a0c93ec93b`), XBOOTLDR (`bc13c2ff-59e6-4262-a352-b275fd6f7172`), Microsoft reserved (`e3c9e316-0b5c-4db8-817d-f92df00215ae`), Windows recovery (`de94bba4-06d1-4d40-a16a-bfd50179d6ac`) or a Linux root type of the Discoverable Partitions Specification |
| **I, internal data**                | not S, not O, `HintSystem=true`                                                                                                                                                                                                                                                                                                                            |
| **R, removable**                    | `HintSystem=false`                                                                                                                                                                                                                                                                                                                                         |

- **A system device** is any block device that:
  - is mounted at a mount point outside `/run/media/`, `/media/`, `/var/mnt/` and `/mnt/` (so `/sysroot`, `/`, `/usr`, `/etc`, `/var`, `/boot`, `/boot/efi`, `/efi`, `/home`, `/var/home` and the image of a `systemd-homed` home all count), read from `/proc/self/mountinfo`, including the automount points of `/efi` and `/boot` that `systemd-gpt-auto-generator` creates;
  - is an active swap device (`/proc/swaps`), except `zram`;
  - is a member of a mounted multi-device btrfs (`/sys/fs/btrfs/<uuid>/devices/`);
  - is the partition named by the EFI variable `LoaderDevicePartUUID` when the boot loader set it (systemd-boot does, GRUB does not);
  - or lies beneath one of these through the kernel's `slaves/` links in `/sys/class/block` (LUKS, dm-verity, loop backing files on a system filesystem).
  - The drive of every such device is class S. With the dm-verity option of D6 the A/B slots are partitions of that drive; with bootc the deployments live inside `/sysroot`; both are covered without naming them. *Amended on 2026-10-06 (A2-8, #150):* the dm-verity option is not taken, so no A/B slot partitions exist; the bootc clause holds.
- **Recomputed** at start, on every `ObjectManager` or mount change, and again inside DK9 before each destructive call.

**DK6. What is impossible, and what is doubly confirmed. (withdrawn, section 7)**

- **On a class S drive nothing destructive exists:** no format of the drive or of any volume, no partition created, deleted or changed (free space included), no image written, no repair, no change of passphrase of its LUKS volumes, no unmount or lock of its system devices, no power-off. The drive page shows its health, its map and its volumes read-only, with one line: "This disk holds the running system. Change it with the installer." The passphrases and keyslots of the system's LUKS volume belong to the guided reseal of `doc_kernel_profile.md` D42 and to Settings, never to this utility. The command-line entry points of DK16 refuse a class S target with the same sentence and make no udisks call.
- **An ESP or XBOOTLDR partition, on any drive,** offers no format, delete, label or type change of its own. It disappears only when the whole drive is formatted, and only on a drive of class O, I or R.
- **Class O and I are doubly confirmed:** the dialog of DK7 with a typed confirmation, then udisks's own `-system` action, which asks an administrator (`auth_admin_keep`). Class O adds the sentence "This disk contains the boot partition of another operating system. That system will no longer start."
- **Class R** gets the dialog of DK7 without typing. With the polkit change of DK20, udisks's default asks no password of any user in the active local session, in `wheel` or not, and asks an administrator in any other session. A removable drive that carries an ESP, such as a live USB stick, adds "This drive can start a computer." and stays class R, so rewriting an installer stick does not ask for typing.
- **The guard is a safeguard against mistakes, not a security boundary.** A member of `wheel` can still format the system disk with `udisksctl`, `mkfs` under `sudo` or any other client of udisks; this document does not claim otherwise. No polkit rule turns the refusal into a boundary for other clients (decision 7).

**DK7. The confirmation names the device. (withdrawn, section 7)** Every destructive action opens one modal `AdwAlertDialog` before any call:

- **It names** the drive by model, capacity and serial number ("SanDisk Ultra, 64.0 GB, serial 4C530001…"), its connection, its device path, and what will be lost: each partition with its label, type, size and used space, and "unknown data" for space udisks cannot read.
- **The buttons** are "Cancel", which holds the focus when the dialog opens and answers Escape, and a destructive-styled button that says the action and its target ("Format SanDisk Ultra"); never "OK". The dialog is announced by Orca with its full text.
- **Typed confirmation, classes O and I:** an entry asks for the last four characters of the serial number as shown; when the drive has no serial, or another connected drive shares it, the capacity in gigabytes as shown. The button stays insensitive until the text matches.
- **The dialog is rebuilt, not reused,** if the drive's objects change while it is open (DK9), and it closes with "The drive changed. Nothing was done." when the target is gone.

**DK8. A mounted device is unmounted first, by an explicit step.** No destructive call is made on a block that has, on itself or beneath it, a mounted filesystem, an unlocked LUKS volume or an active swap.

- **The dialog lists them** ("Data is mounted at /run/media/ada/Data and will be unmounted") and the button says "Unmount and Format".
- **The sequence**, in the `udisks` model: unmount every filesystem beneath the target, deepest first, without `force`; lock every LUKS volume; stop swap (`manage-swapspace`); then re-check DK9; then the destructive call.
- **A failure stops everything before any data is touched.** "Target is busy" reads "A program is still using a file on Data. Close it and try again."; volumes unmounted so far stay unmounted and the dialog says which. The `O_EXCL` open of udisks (section 1) is the second line, not the first.

**DK9. The target is the one the user confirmed. (withdrawn, section 7)** A USB stick can be pulled and another inserted at the same `/dev/sdX`, and a card reader keeps its drive object while its card changes. Immediately before each udisks call that destroys or writes data, the utility re-reads and compares with what the dialog showed: the drive's `Id`, `Size` and `TimeMediaDetected`, the block's object path and size, and for a partition its `UUID` and offset. Any difference aborts with "The drive changed. Nothing was done." The class (DK5) is recomputed in the same step.

**DK10. Formatting and partitions, first release. (withdrawn, section 7)**

- **"Format drive…"** on a whole drive of class O, I or R: a partition table (GPT; "Compatible with older devices" chooses MBR, offered up to 2 TiB), one partition over the whole drive, and a filesystem, in two calls: `Block.Format` with `gpt` or `dos`, then `PartitionTable.CreatePartitionAndFormat`.
- **Partitions:** create in free space, delete, format a partition; set a filesystem label. Not offered: resizing, moving, changing a partition's type, name or flags (DK17).
- **Filesystems offered,** each only when `Manager.CanFormat` answers true: "All systems and devices" exFAT (the default on class R), "Older devices" FAT (vfat), "Windows" NTFS, "Linux" ext4 (the default on class I) and btrfs. With ext4 and btrfs the option `take-ownership` gives the new filesystem's root to the user.
- **Erase:** "Quick" wipes the signatures (the default); "Overwrite with zeros" passes `erase=zero` and says, on a solid-state or flash drive, that zeros do not guarantee the old data is unrecoverable. Firmware erase is not offered (DK17).
- **Check and repair** a filesystem that is not mounted (`Filesystem.Check`, then `Repair` only after its own confirmation, DK7, because a repair can delete damaged files).

**DK11. Encrypted volumes and passphrases. (withdrawn, section 7)**

- **Create:** "Password protect volume (LUKS)" in the format dialog, for ext4, btrfs and exFAT, passes `encrypt.passphrase` and `encrypt.type` `luks2` to `Block.Format`. Two entries, which must match; a strength hint from the `zxcvbn` crate (3.1.1, MIT), which warns and never blocks.
- **Unlock** LUKS1, LUKS2 and BitLocker volumes with a passphrase, optionally read-only; **lock**; **change passphrase** of a volume that is not class S.
- **The passphrase is typed by the user and never stored by Athanor.** It is entered in an `AdwPasswordEntryRow`, whose buffer GTK allocates in non-pageable memory and clears on free (`gtk/gtkpasswordentrybuffer.c` at GTK 4.20.4, set by `adw-password-entry-row.c:157` at libadwaita 1.8.8); the program copies it once into a `Zeroizing<String>` (`zeroize`, a workspace dependency) for the D-Bus call, clears the entry, and drops the copy when the call returns. No key file, no `crypttab` entry, no Secret Service item, no log line. The copies inside the D-Bus message buffers of `zbus` and of the bus are outside the program's control; that is a stated limit.
- **Nothing is remembered in the first release** (decision 3): every unlock asks for the passphrase, and the dialog offers no "Remember" option. Storing it in the Secret Service waits for a specification of the keyring's own confinement.
- **TPM enrolment** of a data volume is not offered (DK17); the TPM is the system disk's (D42).

**DK12. Mounting and safe removal.**

- **Mount and unmount** any filesystem that is not a system device; "Mount read-only" passes `ro`.
- **Programs do not run from a mounted drive by default** (decision 6; the udisks exception of `doc_kernel_profile.md` D23). The image's `mount_options.conf` (DK20) makes `noexec` a default of every mount udisks makes for a session, whichever program asks: this utility, the file manager, the control center. udisks has no selector for removable drives (section 1), so the default also covers an internal data disk mounted by hand; a disk mounted at startup takes the options of its `fstab` entry instead. "Allow running programs from this drive", an unchecked switch on the volume page, passes `exec` for that one mount, which udisks places after the default (section 1); it is not remembered.
- **"Mount at startup"** (withdrawn on 2026-10-06 with the utility, section 7) for a filesystem on a class I drive that is not encrypted (decision 4): one `fstab` entry through `Block.AddConfigurationItem`, which asks an administrator every time, with the filesystem's `UUID=` as the source, the mount point `/var/mnt/<label>` (the label cleaned as DK4, made unique with a number, or the UUID when there is no label), and the options `nofail`, `x-systemd.device-timeout=10s` and `x-gvfs-show`. `nofail` keeps a missing disk from stopping the boot, and the timeout bounds the wait for it. On this image `/etc` is per deployment and merged at each update, so the entry persists across updates and a rollback keeps it. Turning the switch off calls `RemoveConfigurationItem` with the same entry. An encrypted data disk is not offered the switch, because no `crypttab` entry is ever written (DK11).
- **"Open"** on a mounted filesystem shows it in the default file manager through `org.freedesktop.FileManager1.ShowFolders`.
- **"Safely remove"** on a class R drive, one sequence in the `udisks` model shared with the file manager and the control center: unmount every filesystem, lock every LUKS volume, then `Drive.PowerOff` when `CanPowerOff`, otherwise `Drive.Eject` when the media is ejectable. It ends with "You can unplug SanDisk Ultra" or with the failure of DK8; it never forces.

**DK13. Health. (withdrawn, section 7)**

- **ATA drives** (`Drive.Ata`): `SmartSupported`, `SmartFailing`, `SmartNumBadSectors`, `SmartNumAttributesFailing`, `SmartTemperature`, `SmartPowerOnSeconds`, `SmartSelftestStatus`. **NVMe** (`NVMe.Controller`): `SmartCriticalWarning` (`spare`, `temperature`, `degraded`, `readonly`, `volatile_mem`, `pmr_readonly`), `SmartTemperature`, `SmartPowerOnHours`, and from `SmartGetAttributes` `percent_used`, `avail_spare`, `spare_thresh`, `media_errors`, `unsafe_shutdowns`, `total_data_written` (`udiskslinuxnvmecontroller.c`, `handle_smart_get_attributes`).
- **One summary per drive,** in words: "Good"; "Has problems: 12 bad sectors" (any failing attribute, bad sectors, `media_errors` above zero, `percent_used` at 90 or more, `avail_spare` at or below `spare_thresh`); "Likely to fail soon. Copy your data now." (`SmartFailing`, or a critical warning other than `temperature`). The temperature is shown in the user's unit; a value of 0 kelvin, which udisks reports when the drive gives none, is not shown. A drive without health data says "Health not available for this drive", which is the common case behind USB bridges.
- **Refresh:** udisks refreshes the data itself; the page calls `SmartUpdate` once when it opens. **Self-test:** short and extended, start and abort, under the `selftest` actions (administrator).
- **No warning when the window is closed.** GNOME's notifier does not run in this session (section 1); a background warning is excluded from this release (DK17).

**DK14. Disk images. (withdrawn, section 7)** The first release writes an image to a drive and attaches an image read-only; it does not create images (decision 1), so the program creates no file of the user's.

- **"Write disk image…"** on a drive of class O, I or R, and as the handler of `application/x-cd-image` and `application/x-raw-disk-image`, so "Open with" in the file manager keeps working when GNOME Disks leaves. Raw images only (`.iso`, `.img`, `.raw`); a compressed image is refused with "Decompress the image first" (DK17).
- **Optional expected SHA-256:** a field accepts the checksum the publisher gives; when it is filled, the image is hashed before anything is written, and a mismatch writes nothing.
- **The write** goes through one descriptor from `Block.OpenDevice` in mode `rw` with `O_EXCL` and `O_DIRECT`, after DK8 and DK9. The image is copied in aligned blocks while its SHA-256 is computed (`sha2`, a workspace dependency); the same descriptor then reads back the written length and hashes it. Holding one exclusive descriptor across write and verify keeps the automounter and any other program off the drive until the end (spike S1). The result says "Written and verified", with the checksum shown in full, or "Verification failed: the drive returned different data", which usually means a failing or counterfeit drive.
- **Progress** shows bytes, rate and the time left; "Cancel" stops after the current block and says the drive now holds an incomplete image. While a write runs, closing the window asks "Stop writing?"; the process holds the application open until the answer.
- **"Attach disk image"** (`Manager.LoopSetup`, `read-only` always), as the handler `gnome-disk-image-mounter` was: the file is opened by the utility and its descriptor passed; the file manager then shows the volumes, mounted by its automount policy. The kernel parses the image's filesystem as it parses a USB stick's; that exposure is the same as GNOME's and is stated, not removed.
- **The image file is chosen** through the file chooser portal (`doc_portal.md`), by drag and drop, or by "Open with" from the file manager. It must lie in a folder DK15 lets the program read; otherwise the program says which folders it can read.

**DK15. Confinement of the program. (withdrawn, section 7)** At start, before GTK opens a display, the program restricts itself; every later step runs under these limits.

- **Landlock** (`landlock` 0.4, a workspace dependency), as the bar and Software do:
  - read: `/usr`, `/etc`, `/proc`, `/sys` (topology for DK5, health is over D-Bus), the XDG data directories, and for images the user's XDG user directories (Desktop, Documents, Downloads, Music, Pictures, Public, Templates, Videos, as `xdg-user-dirs` names them), `/run/media/$USER`, `/var/mnt` and `/mnt`. Hidden directories of the home, where keys and tokens live, are not readable;
  - write: the list the bar has (its runtime directory, dconf, its cache, `/tmp`, `/dev/dri`) and `$XDG_STATE_HOME/athanor-disks/` for window state;
  - network: no TCP bind or connect (Landlock ABI 4). The program needs no network.
- **Not dumpable.** `prctl(PR_SET_DUMPABLE, 0)` at start, as `ssh-agent` does: on this image `kernel.yama.ptrace_scope` is 0 (read on the desktop, 2026-10-05), so without it any process of the user could attach to the utility and read a passphrase, and a core dump could hold one. The cost is no core dump on a crash; the panic message still reaches the journal before the abort.
- **What it still reaches,** stated: the system bus, where udisks and polkit decide; the session bus; the descriptors udisks gives it. With `panic = "abort"`, a crash during DK14 leaves an incomplete image on the target, reported as DK14's cancel; a crash during a udisks job leaves the job running in `udisksd`, whose result the next start shows.
- **The unit** is the transient application unit of BR2 when started from the bar, the dock or the launcher; the program's own restrictions apply whichever way it starts.
- **`udisksd` itself** is outside this program. It is hardened by the drop-in of DK20 (decision 8), a system change this program does not depend on.

**DK21. USB devices blocked by USBGuard.** A mass-storage stick is blocked by the policy (section 1) and the policy does not change. A person allows it, one device at a time, in the unlocked session, through `usbguard-dbus` and polkit. Everything stays blocked while the session is locked.
- **The lock side is not this document's.** The root service of `doc_lock_and_prompts.md` (LP4) sets `InsertedDevicePolicy` to `block` unless the active user session of seat0 is unlocked, and to `apply-policy` then; under `apply-policy` a stick still matches no rule and stays blocked. A stick inserted while locked therefore stays blocked after unlock and is offered like any other (below). Until LP18 step 10 the old hook leaves a lock-screen insertion to `apply-policy`: a stick is blocked all the same by the implicit target, but a keyboard is not (declared in the lock document).
- **Never a static allow for class `08`.** No file of the image allows mass storage, the baseline's rejection of an interface set that mixes HID with storage, CDC or wireless is untouched, and a device whose target is `reject` is never offered, by this program or by the notice.
- **The model.** One module `usbguard` in `system/athanor-services` beside `udisks` (DK3), on `zbus`: typed proxies for `org.usbguard.Devices1` generated once as DK3 does, a call `list_blocked()` (`listDevices("block")`, run at start and on every unlock, so a stick inserted while locked is found) and the two signals `DevicePresenceChanged` and `DevicePolicyChanged`. A device is offered only when its target is block (1) and an interface in `with-interface` begins with `08:`. The module serves this program, the control center's Devices page (CC8) and the session notice, and keeps no state beyond the live list.
- **Two actions.** "Allow once" calls `applyDevicePolicy(id, 0, false)`: the device is authorised for this connection only, no rule is written, and a replug is blocked again. "Allow always" calls `applyDevicePolicy(id, 0, true)`: USBGuard writes the device's own rule (section 1) and the same stick is allowed from then on. Both are the one polkit action `org.usbguard.Devices1.applyDevicePolicy`; the action id carries no argument, so polkit cannot tell them apart and the program, not polkit, decides what it offers.
- **What a permanent rule pins** is what USBGuard writes by default, kept as it is: `id` (VID:PID), `serial`, `name`, `hash` (a digest of the descriptors, name and serial), `with-interface equals { ... }` (the exact interface set, so a device that later presents another interface does not match), `with-connect-type` and `parent-hash` (the hub or controller it was allowed behind). `via-port` is not pinned (`DeviceRulesWithPort` stays false): a person moves a stick between the sockets of one machine, and the parent hash already ties the rule to the topology. "Allow always" is offered only when the serial is non-empty: without one the hash is shared by every unit of the model and the rule would allow them all, so such a stick has "Allow once" only. Spike S6 settles whether the parent hash makes a stick allowed on the laptop's own port fail behind a dock.
- **Authorisation.** The caller's bus name is the polkit subject, and upstream's default for `applyDevicePolicy` is `auth_admin` (section 1). That asks an administrator for every stick, and a user outside `wheel` cannot answer. `yes` would let any process of the user in the active session, which logind keeps "active" while the screen is locked, allow a device with no prompt. The rule, a polkit change the maintainer approved on 2026-10-05 (decision 11; the file is `forge/specs/athanor-system-tweaks/SOURCES/etc/polkit-1/rules.d/20-athanor-usbguard.rules`, not `polkit.rs`):
  ```js
  polkit.addRule(function(action, subject) {
      if (action.id == "org.usbguard.Devices1.applyDevicePolicy" &&
          subject.local && subject.active) {
          return polkit.Result.AUTH_SELF;
      }
  });
  ```
  `AUTH_SELF` asks the user's own password in our polkit agent, which holds requests while the session is locked (LP11), so nothing is allowed behind the lock. Inactive and remote sessions stay at upstream's refusal. `listDevices` stays at `yes`; `appendRule`, `removeRule` and `setParameter` stay at `auth_admin` and nothing here calls them. The design works without the rule, with an administrator's password.
- **Not covered, stated.** Code running as the user can call `applyDevicePolicy` and, with the user's password, allow a stick: the threat of any `AUTH_SELF` action, and no larger than what such code can already do. USBGuard's rules live in `/etc/usbguard`, which is per deployment and survives updates, so they are backed up and rolled back with `/etc`.
- **Where the notice lives.** The notification and its two buttons belong to `doc_session_daemons.md` SD12: `athanor-sessiond` raises the notice in the unlocked session (amendment received, section 3); the list of allowed devices is SD13. This document gives it the `usbguard` module, the rule that only blocked storage with a serial gets "Allow always", and the text: the device's name and serial as plain text (SH12), the size when known, "Blocked USB storage device".

## 6. Decisions taken

All taken by the maintainer on 2026-10-05; each followed the draft's recommendation.

1. **Disk images.** Write an image to a drive and attach one read-only; no image creation (DK14). Reason: it covers the installer on a USB stick and the file manager's ISO handler, and keeps the program from writing files.
2. **Benchmark.** None (DK2, DK17). Reason: nothing asks for it, a synthetic number is easy to misread, and a write benchmark is one more destructive path.
3. **Remembering a LUKS passphrase.** Never in the first release; every unlock asks (DK11). Reason: the keyring every process of the user can query has no confinement specified yet, and a TPM keyslot would entangle data volumes with the reseal of D42.
4. **"Mount at startup" for internal data disks** (lapsed on 2026-10-06 with the utility, section 7). An `fstab` entry through udisks, with `nofail` and a 10-second device timeout (DK12). Reason: asking an administrator at every login is what users work around by hand, and `nofail` keeps a missing disk from stopping the boot.
5. **The polkit rule on mount and eject.** Remove the udisks `addRule` of `10-athanor-wheel-admin.rules` and return to udisks's defaults, as a system change of its own (DK20 A). Reason: the rule asked a non-administrator a password to mount yet none to format, and let `wheel` mount from remote sessions.
6. **Programs on removable media.** `noexec` by default, with a per-mount switch to allow programs (DK12, DK20 B; the switch lapsed, decision 14); `doc_kernel_profile.md` D23 was amended the same day with an explicit exception for udisks mounts, so the two documents agree. Reason: a found USB stick should not run code by a double-click; the file manager inherits the default.
7. **The refusal on the system disk.** A safeguard in this program only, no polkit rule (DK6). Reason: the threat is a mistake in this interface, and an administrator reaches the disk through `sudo` anyway.
8. **Hardening `udisksd`.** A drop-in with options that create no mount namespace, each kept only if the spike shows every operation working, as a system change of its own (DK20 C). Reason: `udisksd` parses metadata of untrusted devices as root, and the zero-trust rule asks every daemon to be confined.
9. **udisks proxies.** Own `#[proxy]` declarations generated once with `zbus-xmlgen` and checked in (DK3). Reason: no LGPL-2.1 relinking obligation, no GNU gettext build, and CC3 declares every service's proxies the same way.
10. **USB storage blocked by USBGuard.** Install `usbguard-dbus`; a blocked storage device is offered "Allow once / Allow always" in the unlocked session, authorised by polkit; everything stays blocked while locked (DK21, DK20 D). Taken 2026-10-05. Reason: the policy already blocks storage and stays as it is; a person allows a device, never a rule for the class.

11. **The polkit action for `applyDevicePolicy` (a polkit change).** `AUTH_SELF` for a local, active subject (DK21, DK20 D): the person types their own password in our agent, which holds the request while the session is locked. Taken 2026-10-05. Reason: anyone, in `wheel` or not, can allow their own stick, and no process of the user can allow a device without the person.
