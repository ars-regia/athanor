## 2. Decisions

**PT1. Which interfaces are Athanor's.** One file, `/usr/share/xdg-desktop-portal/athanor-portals.conf`, shipped by `xdg-desktop-portal-athanor`, chooses every backend. `default=none` means an interface that is not listed is not offered. The deprecated `UseIn` key leaves `athanor.portal`, whose `Interfaces` line lists exactly what the backend implements.

| Interface                                                                         | Backend                                      | Why                                                                        |
| --------------------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| Settings                                                                          | `athanor` (decision 1)                       | the appearance of VL5, AX2 and LN15                                        |
| FileChooser                                                                       | `athanor` from PT18 step 3; `gtk` until then | PT7; the gtk dialog works today, the current athanor one does not          |
| Access                                                                            | `athanor` from step 2; `gtk` until then      | PT6; it is also the prompt for Camera, Location, Screenshot and Background |
| Screenshot                                                                        | `athanor`                                    | PT8                                                                        |
| ScreenCast                                                                        | `athanor` from step 5; `none` until then     | PT9; release 5 already withdrew the fixed node-42 answer                   |
| Inhibit                                                                           | `athanor` from step 2; `gtk` until then      | PT11                                                                       |
| Background                                                                        | `athanor`                                    | PT12                                                                       |
| AppChooser, Print, Account, Email, DynamicLauncher, Notification                  | `gtk`                                        | decision 6                                                                 |
| Secret                                                                            | `gnome-keyring`                              | the keyring the session already runs (lock decision D11 keeps it)          |

- **Camera and Location** need no backend of their own: the frontend implements both and asks through Access. **Microphone** is not a portal: a Flatpak reaches the audio server through its PulseAudio socket permission.
- **The frontend's own portals** (OpenURI, Trash, NetworkMonitor, ProxyResolver, MemoryMonitor, PowerProfileMonitor, GameMode, Realtime, Documents) are untouched.

**PT2. Programs and crates.** One backend process (decision 2).

- `forge/specs/athanor-xdg-desktop-portal-athanor`, the package `xdg-desktop-portal-athanor`, keeps its name, its bus name `org.freedesktop.impl.portal.desktop.athanor` and its executable `/usr/libexec/xdg-desktop-portal-athanor`, so the frontend and the dbus activation file need no rename. Its crate is rewritten.
  - **Resident and hidden**, as the launcher and the control center: GTK4 and libadwaita on the main thread; zbus on a Tokio thread, handed a `Handle` (CC3); the PipeWire producer on its own thread, with its own loop; the Sal consent window of PT15 on a thread of its own, with its own Wayland connection beside GTK's, its parent window to be imported through `zxdg_importer_v2` as PT4 imports the GTK dialogs' (*amended on 2026-11-17*); Sal sets a parent today only between its own toplevels, through `xdg_toplevel.set_parent` (`system/athanor-sal/src/driver.rs`), and has no xdg-foreign import, which step 7 of PT18 adds. *For the file chooser* (*approved, 2026-11-21*): the main thread runs a resident Sal run in place of GTK's main loop, with GLib's default context driven inside Sal's loop (`GlibSource` of `athanor-sulphur-client`, as the control center runs it), so dconf, the GIO monitors and the view's enumeration stay on one thread; the zbus thread is unchanged, and the two exchange requests and answers through a channel that wakes Sal's loop. The chooser is drawn there, with no GTK4, no libadwaita and no Sal thread beside GTK's for it. The run opens its Wayland connection at the first chooser request and keeps no window at rest; a failed connection answers that request with an error and the process goes on, so Settings answers with no compositor reachable. The GTK4 and libadwaita main thread described above remains the text of the access dialog (PT6) and the screen-sharing picker (PT9) only, until a revision of their own. (*approved, 2026-11-21*) From step 3 of PT18 those GTK dialogs share the main thread with Sal's run and need no loop of their own: GTK runs on GLib's default main context, which Sal's run dispatches through `GlibSource` of `athanor-sulphur-client`: it acquires the context of `MainContext::default` (`system/athanor-sulphur-client/src/glib_loop.rs:74`) and runs its sources with `g_main_context_dispatch` (`:220`). It maps a window only while a dialog is open. Its overlay layer surfaces are created once per output, pinned and kept mapped (`doc_launcher.md` LA8, as OD7 of `doc_osd.md`): hidden, one holds no content, an empty input region, no keyboard interactivity and a size of 1×1 on the background layer; shown, it takes the layer `overlay` and the interactivity the rule names.
  - **Its windows:** the file chooser (PT7), the access dialog (PT6), the screen-sharing picker (PT9), and the RemoteDesktop consent dialog (PT15), which is drawn with Sal, Athanor's own toolkit (`athanor-sal`), and adds no GTK interface (*amended on 2026-11-17*). Under the amendment of 2026-11-18 (`doc_files.md` revision 3, decision 8), the file chooser is a Sal window too: it runs in the main thread's Sal run (above, *approved, 2026-11-21*), in this process and under its confinement (PT3), never in the file manager's, and it imports its parent window through `zxdg_importer_v2` as the consent dialog does, the import Sal gains with whichever of steps 3 and 7 of PT18 lands first, and the other reuses. The access dialog and the screen-sharing picker are unchanged by that amendment. Not taken (`doc_files.md` revision 3, decision 8): a Sal chooser in a process of its own per request, option (b); and the gtk backend's chooser through release 1.0, option (c), which leaves a GTK dialog in the session. **Its overlays:** the screenshot and colour-picking overlays (PT8), as pinned layer-shell surfaces (PT3).
- `system/athanor-portal`, a new library with no GTK type (SH4), holds every decision the tests must reach without a display: validation of each request's options; the Settings values (PT5); the bookkeeping of requests, sessions and inhibitors; the Background state (PT12); the restore data of PT9; the admission of `os.athanor.Portal1` callers (PT10). It holds the interface definitions, generated with `zbus-xmlgen` from the XML of xdg-desktop-portal 1.20.4 and committed with the tag they came from, as disks decision 9 did for UDisks2. The `ashpd` crate's backend feature (0.13.13, MIT, crates.io, 2026-10-05) is not used: it would add a dependency for what generated proxies give, and it has no Inhibit backend.
- `forge/specs/athanor-recorder`, a new program with no GTK and no Wayland connection: the shell's capture client (PT13).
- **Why not upstream, and who maintains it** (scope budget, ADR 0051, A2-14; `doc_shell.md` SH3). Upstream backends exist: xdg-desktop-portal-gnome, -wlr and -cosmic, and xdg-desktop-portal-gtk, which the image uses today as a fallback. None of them serves this session as one piece.
  - The gtk backend inhibits idle only ("Inhibiting other than idle not supported", section 1), cannot show `athanor-files-view` in its chooser, and gives `color-scheme` and `contrast` 0 and no accent; its mirror-derived Settings values would also double the `SettingChanged` signals of ours (section 6, decision 1).
  - xdg-desktop-portal-gnome is not installed and is written for another shell; the wlr and cosmic backends are written for other compositors and need globals that cosmic-comp withholds from any security context but CosmicPanel's (PT3). No `xdg-desktop-portal-cosmic` is in `forge/config/packages.json`.
  - The recorder and the capture surfaces have no upstream equivalent that fits the bar's indicator and the confinement of PT3.
  - **Owner:** the maintainer owns `xdg-desktop-portal-athanor`, `system/athanor-portal` and `athanor-recorder`, and answers for their upkeep against each xdg-desktop-portal release.
  - **Upstream first, never dependent on upstream.** Every component here works if upstream never accepts a change. A small fix to an upstream project goes upstream at once; a large feature starts with an upstream issue or discussion. A patch we carry meanwhile is listed and dropped when upstream takes it.
- **Reused, not rewritten:** `athanor-files-view` (FM17), `athanor-sulphur-client` (its outputs, its toplevel model, its capture code and its layer-shell support; the only crate that knows COSMIC), `athanor-style`, `athanor-i18n`, `athanor-unit` (`sandbox`, `dirs`, `journal`), `athanor-preview` for thumbnails (LA6, FM10).

**PT3. Confinement.**

- **The backend's unit**, `xdg-desktop-portal-athanor.service`, replaces today's transient activation: the dbus service file gains `SystemdService=xdg-desktop-portal-athanor.service`, as xdg-desktop-portal-gtk's does (`/usr/share/dbus-1/services/org.freedesktop.impl.portal.desktop.gtk.service`). The unit: `Type=dbus`, `BusName=org.freedesktop.impl.portal.desktop.athanor`, `PartOf=` and `After=graphical-session.target`, `Slice=session.slice`, `Restart=on-failure`, `NoNewPrivileges`, `ProtectSystem=strict`, `PrivateTmp`, `SystemCallFilter=@system-service`, the kernel and control-group protections of `athanor-shelld.service`, `RestrictAddressFamilies=AF_UNIX`, `RuntimeDirectory=xdg-desktop-portal-athanor` with `RuntimeDirectoryPreserve=yes`, `CacheDirectory=xdg-desktop-portal-athanor` with `XDG_CACHE_HOME` pointing there, `GSK_RENDERER=cairo` (SH4). `ProtectHome` is not set: the new-folder rule below needs the home mounted writable, and Landlock bounds it instead. *For the file chooser* (*approved, 2026-11-21*): `GSK_RENDERER=cairo` serves the GTK dialogs of PT6 and PT9, and the chooser needs no renderer variable, since Sal draws on the CPU. `ProtectSystem=strict` mounts the home and `/run/media` read-only for the unit whatever Landlock grants, so the unit carries `ReadWritePaths=%h -/run/media`, the `-` so that an absent `/run/media` does not stop the unit in its namespace setup. The user unit `athanor-skel-sync.service` already pairs `ProtectSystem=strict` with `ReadWritePaths=%h` (`forge/specs/athanor-system-services/SOURCES/usr/lib/systemd/user/athanor-skel-sync.service:17-19`). The image ships its own `d /run/media 0755 root root`, so that this line and Landlock's make-directory root have their anchor from boot and a drive mounted later lies beneath it (section 6, decision 19). (*approved, 2026-11-21*) The line is `/usr/lib/tmpfiles.d/xdg-desktop-portal-athanor.conf`, in the backend's package (the spec's `%files`). udisks2 ships the same line (`/usr/lib/tmpfiles.d/udisks2.conf`, udisks2 2.11.2); systemd-tmpfiles applies an identical line again without a message and logs only a line that conflicts, which it then ignores (systemd 262, tested on 2026-11-21), so the duplicate costs nothing. The backend checks itself that `/run/media` exists, before `restrict_writes_and_mkdir`, and not through `athanor_unit::dirs::existing`, which skips a missing path silently: when it is absent, the backend logs at err priority with the path and confines without that root, so New Folder and saves beneath `/run/media` are refused and the Settings portal in the same process stays up. That fails closed, since it means fewer writes. Whether a drive mounted after the unit started is writable in the unit's mount namespace is decided by the sandbox test of PT16 before step 3 merges. `RuntimeDirectory=xdg-desktop-portal-athanor` and `CacheDirectory=xdg-desktop-portal-athanor` join the unit with the first step that writes there, screenshots in flight (PT8); the chooser writes in neither.
- **The backend's liveness** (*amended on 2026-11-21*, maintainer decision, 2026-11-21). The unit sets `WatchdogSec=` and `NotifyAccess=main`, and the backend sends `WATCHDOG=1` only after a roundtrip on its own bus connection has succeeded, as `doc_session.md` SN6 says for `athanor-shelld`, `athanor-sessiond`, `athanor-idle` and this backend; a backend whose loop runs while its connection is wedged is therefore ended by the manager once no ping has arrived for `WatchdogSec=`, and restarted as its unit's `Restart=` says, as for any other crash. *Amended on 2026-11-22 (maintainer decision, 2026-11-22):* the unit sets `WatchdogSec=30s`, the value of `doc_session.md` SN6 for the four session daemons.
- **Landlock**, applied at start before GTK initialises and before any thread starts (`athanor_unit::sandbox::ensure_single_threaded`), so every thread runs under it:
  - read access everywhere the user can read, as the chooser must browse;
  - write access only beneath the unit's runtime directory (screenshots in flight, PT8), the unit's cache directory, the dconf runtime directory, `/tmp` and `/dev/dri`. (*approved, 2026-11-21*) The runtime and cache directories are granted with the step that writes there (PT8), and `/dev/dri` only with a GTK dialog of PT6 or PT9; for the file chooser the write roots are `$XDG_RUNTIME_DIR/dconf` and `/tmp`. The chooser's Ctrl+H (PT7) is a GSettings write, and a GSettings write needs two things of the client process (dconf 51, the GIO module `libdconfsettings.so`; dconf's `shm/dconf-shm.c`): the value goes to `dconf-service` as a `Change` call of `ca.desrt.dconf.Writer` on the session bus, and `dconf-service` alone writes the database under `$XDG_CONFIG_HOME/dconf`; and the client opens the shared-memory flag `$XDG_RUNTIME_DIR/dconf/user` read-write, creating it, and its directory with mode 0700, when they are absent (`dconf_shm_open`), the flag by which it learns that a value changed; the unit already declares `RuntimeDirectory=dconf` with mode 0700, preserved at the stop (`forge/specs/athanor-xdg-desktop-portal-athanor/xdg-desktop-portal-athanor-1.0.0/xdg-desktop-portal-athanor.service`), and Landlock grants that directory by the descriptor `dirs::private_dir` checked (`forge/specs/athanor-xdg-desktop-portal-athanor/xdg-desktop-portal-athanor-1.0.0/src/main.rs:69`);
  - beneath `$HOME` and `/run/media`, only `LANDLOCK_ACCESS_FS_MAKE_DIR`, for the chooser's "New Folder". The backend never writes, renames or removes a user's file. A function `restrict_writes_and_mkdir` joins `athanor_unit::sandbox` for this;
  - no TCP (`athanor_unit::sandbox::deny_tcp`).
    If any step fails the process logs it and exits, as the bar does (`forge/specs/athanor-bar/athanor-bar-1.0.0/src/start.rs:170-173`).
- **The Wayland socket.** The backend uses the main socket, as the bar does. Capture, layer-shell overlays and the import of a parent window need globals that cosmic-comp withholds from any security context but CosmicPanel's (spike P4), and a capture backend in a context would have to claim that engine name, which Athanor does not do. *On Sulphur* (*approved, 2026-11-21*): the import of a parent window and a dialog's modality (`zxdg_importer_v2`, `xdg_wm_dialog_v1`) are standard globals, offered inside a security context as well (`forge/specs/athanor-sulphur/athanor-sulphur-1.0.0/data/globals`). The main socket is kept for capture and the overlays: Sulphur offers the capture globals (`ext_image_copy_capture_manager_v1` and its sources) and the top and overlay layers of `zwlr_layer_shell_v1` only outside a security context, and only to a client its allow-list names by unit and executable (`doc_own_stack.md` OS4, OS17; `data/privileged-clients`), the line the first step that captures adds for this unit (PT8).
- **Only the frontend may call it.** Every call on an `org.freedesktop.impl.portal.*` interface whose sender is not the current owner of `org.freedesktop.portal.Desktop` is refused with `AccessDenied` and a journal line, as release 6 already does (`caller.rs`, kept by the rewrite). Without this, any process on the session bus could call `Screenshot` with `permission_store_checked` set and take the screen without a prompt.
- **A declared limit, ended for `confined` applications by the launch broker** (`doc_session_daemons.md` SD9, SD22 step 6): the broker's filtered bus does not expose `org.freedesktop.host.portal.Registry`, so a `confined` application cannot register another application id. The limit stands for the `unconfined` class, whose host application has the whole session bus and may register any application id through `org.freedesktop.host.portal.Registry` (`data/org.freedesktop.host.portal.Registry.xml`, 1.20.4). A grant given to a host application's id therefore protects nothing against another host application. Flatpak applications are identified by the frontend from their sandbox and are not affected.
- **The recorder** confines itself the same way at start: writes only beneath `$XDG_PICTURES_DIR/Screenshots`, `$XDG_VIDEOS_DIR/Screencasts` and its GStreamer registry cache, no TCP. It opens no Wayland connection. It also reads, and never writes, beneath the backend's runtime directory, because the PNG of PT8 is born there; it never removes that original, which the backend's own sweep does (PT8).
- **Accepted risk** (confirmed by the maintainer on 2026-10-08). The backend holds the main Wayland socket (capture, layer-shell) and reads all of `$HOME` (the chooser) in one process. The mitigations are this Landlock ruleset, the frontend-only rule and decoders outside the process; a second process for the capture producer was considered and not taken (section 6, decision 2).

**PT4. Requests, windows and names.**

- **Request and session objects.** Every method that takes a `handle` exports `org.freedesktop.impl.portal.Request` on it until it answers, and `Close` cancels the dialog or overlay, answering 1. ScreenCast, RemoteDesktop and the Inhibit monitor export `org.freedesktop.impl.portal.Session` with `Close` and `Closed`.
- **Parent windows.** A `parent_window` of the form `wayland:<handle>` is imported with `zxdg_importer_v2` and set as the parent of the dialog's toplevel, so the dialog sits over its application. An empty or unknown handle (X11 applications, or `x11:` handles) gives an unparented dialog centred on the active output (spike S3).
- **Names and icons.** A dialog names the application by the `Name` and `Icon` of `<app_id>.desktop`. With no desktop file it shows the id. For an empty id (a host application that did not register) it says "An application", as the frontend's own prompt text does (`src/screenshot.c:270-276`).
- **The grant button waits.** In the access dialog and the sharing picker, the button that grants is insensitive for the first 500 ms after the dialog maps, so an application cannot move a click target under the pointer and get a grant from a click meant for itself. The keyboard default is always the refusing button.
- **Strings** go through `athanor-i18n`. Every dialog is reachable from the keyboard alone, with names and roles in AT-SPI (ST7).

**PT6. Access: the application permission prompt** (F-lock-30).

- `AccessDialog` draws one libadwaita dialog: the application's icon and name (PT4); the title, subtitle and body the frontend passes; the `choices` it passes; the `deny_label` and `grant_label`, defaulting to "Deny" and "Allow". The answer is 0 for grant, 1 for deny, 2 when the dialog is closed by `Close` or the backend ends.
- **Modal** requests (the default) are transient for the parent and block it, as libadwaita's dialogs do. With no parent the dialog is a toplevel on the active output.
- **Camera and Location** reach the user through this dialog, called by the frontend. The frontend records the answer in its permission store (tables `devices` and `location`, unverified), and Settings shows and revokes those grants (`doc_settings.md`).
- **No grant is remembered here.** The backend keeps no permission of its own; the frontend's store is the only record, so revoking a grant in Settings revokes it everywhere.

**PT7. FileChooser.**

- **The view** is `athanor-files-view` (FM17): the directory model with sorting and hidden files, list and grid, the path bar with an editable location (Ctrl+L), the sidebar of FM12 and FM14. In the chooser (*approved, 2026-11-21*) the sidebar shows Home, the XDG user directories, the bookmarks and the removable filesystems already mounted beneath `/run/media/<user>`; Recent is not shown, as PT15 excludes it from the chooser, and is read only in the file manager's window. Hidden files follow `show-hidden` of `org.athanor.desktop.files` (`doc_files.md` FM18), shared with the file manager and saved (section 6, decision 21): the chooser's Ctrl+H writes the key through GIO only after looking up the schema and the key exactly as the view does, and when either is missing the toggle applies to the open dialog and nothing is written, so the backend never aborts. A write that fails, a key locked by dconf's lockdown for one, is logged at warning priority and changes only the open dialog; it never panics. The dialog adds what a chooser needs and nothing a file manager does: the filter menu, the `choices` rows, the name field of a save, the accept button. Under the amendment of 2026-11-18 (PT2), the view and these rows are drawn with Sal (`doc_files.md` FM17), and the dialog is the Sal window PT2 describes, which answers how the backend hosts a Sal view, the question FM17 leaves to this document.
- **Thumbnails** come through the callback FM17 provides: images and PDFs are rendered by `athanor-preview-render` (LA6) and held in memory; the backend reads the shared thumbnail cache (FM10) but does not write it. Other types show their icon.
- **`OpenFile`** honours `multiple`, `directory`, `filters`, `current_filter`, `choices`, `accept_label`, `modal` and `current_folder`. It answers `uris`, `choices`, `current_filter` and `writable` true, so an editor can save back to the file it opened. Amended (maintainer decision 2026-10-15, #144): `writable` follows the real access, true when the user can write to the file and false for one that is read-only; the backend's tests cover both answers, in the change that lands PT18 step 3.
- **`SaveFile`** honours `current_name`, `current_folder`, `current_file`, `filters`, `current_filter` and `choices`. An existing name asks "Replace", with Cancel as the default. The backend returns the URI; the application writes the file through the document the frontend exports.
- **`SaveFiles`** asks for a folder and returns one URI per name in `files`, adding " (2)", " (3)" before the extension when a name exists, so nothing is overwritten without a question.
- **The persistence paths of `doc_threat_model.md` TM3** (*approved, 2026-11-21*). Every check is on canonical paths, against TM3's list canonicalised the same way (`/home` is a link to `/var/home`), which is held as one constant that `scripts/verify.py` checks against TM3. A target's canonical path is its own when it exists, and its canonical parent with its name when it is absent (a new name of a save, New Folder); a dangling link as the target is refused for writing, and any error of canonicalisation (a dangling link in an intermediate component, an absent parent, a permission error) refuses the write and never falls back to the path as given. `SaveFile` and `SaveFiles` refuse a target that is, or lies beneath, a TM3 path, with a message that names Settings; `OpenFile` answers `writable` false for a file that is, or lies beneath, one, and for a picked folder (`directory` true) that is, lies beneath or contains one (`~`, `~/.config`, `~/.local/share`), since a write grant on a folder covers its subtree; New Folder is refused beneath one, and is the one write the backend performs itself (*approved, 2026-11-21*): the backend holds an `O_PATH | O_DIRECTORY` descriptor of `/`; it opens the parent with `openat2(root_fd, <canonical path without the leading />, RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_BENEATH)`, as `athanor-backup` opens a parent inside a snapshot (`forge/specs/athanor-backup/athanor-backup-1.0.0/src/main.rs:235-246`). Both open the parent `O_PATH | O_DIRECTORY`; they differ in two ways. From a descriptor of `/`, `RESOLVE_BENEATH` constrains nothing, and `RESOLVE_NO_SYMLINKS` is what protects the walk. `RESOLVE_NO_XDEV`, which `athanor-backup` sets, is left out on purpose, since `/run/media/<user>/<label>` is a mount of its own. The backend reads that descriptor's path once, through `/proc/self/fd/<n>`, compares it with the canonical TM3 list and makes no second look-up by path; and it creates the folder with `mkdirat(parent_fd, name)`, the name one component that is neither `.` nor `..`, and the parent with the name not itself a TM3 path (`autostart` in `~/.config`, for one). A rename between that read and the `mkdirat` lies outside the check, as it does for the answer's URI; a confined application cannot make one beyond its own write grant. A `current_folder` or `current_file` in a TM3 path opens the home instead. The answer carries the canonical URI that was checked, never the one given, so a link re-pointed after the check cannot redirect it; a swap by another process of the same user after the answer is outside what the backend can check. Not taken: allowing the write because the user picked the file, since a deceptive application can suggest `~/.bashrc` as `current_file`, and the document store's write grant outlives the dialog.
- **Without `current_folder`** the dialog opens where that application's last request ended in this session, else in the home. Nothing is persisted.
- **New Folder,** the one write the backend performs itself (above; *approved, 2026-11-21*), runs under the Landlock rule of PT3; the hidden-files key is written by `dconf-service` (PT3). The chooser mounts nothing (*approved, 2026-11-21*): its sidebar lists the removable filesystems already mounted, and mounting, unlocking and ejecting wait for `doc_files.md` FM21 step 4, which waits for the polkit agent of `doc_lock_and_prompts.md` LP18 or for `doc_disks.md` DK20 A (`doc_files.md` revision 3, decision 14); a mount added then goes through the `udisks` module of `doc_disks.md` (DK3) and UDisks2's own polkit actions only. Until then a stick that is not yet mounted is out of the chooser's reach, which the gtk chooser reached through gvfs, and acceptance 4 holds for a mounted stick only. (*approved, 2026-11-21*) The gate of that switch is one check on the reference laptop, run before step 3 of PT18 switches FileChooser: with `athanor-sessiond`'s automount (`doc_session_daemons.md` SD11, built at SD22 step 5 on the `udisks` module of `doc_disks.md` DK3), a stick inserted while no window of the file manager is open is mounted under `/run/media/<user>/` and shows in the chooser's sidebar. Until it passes, FileChooser stays on gtk. The chooser never formats, ejects, renames or deletes.

**PT8. Screenshot and PickColor.**

- **A non-interactive `Screenshot`** captures every output through ext-image-copy-capture, composes them in the layout's logical coordinates at the highest output scale (spike S6), and writes a PNG beneath the unit's runtime directory. It answers its `file://` URI; for a Flatpak the frontend turns it into a document (`src/screenshot.c:116-133`). It runs only with `permission_store_checked` true: the frontend has then asked through Access and recorded the grant in table `screenshot` (`src/screenshot.c:228-300`). A request without the flag is treated as interactive, so it never captures silently.
- **An interactive `Screenshot`** freezes every output and shows the pinned overlay of each output (PT3): a selection rectangle, a window mode in which a click picks a toplevel (captured alone, through its foreign-toplevel source), and a whole-screen mode. Enter or the capture button confirms; Escape cancels and answers 1. On confirmation the backend writes the PNG as above, copies the image to the clipboard while the overlay still holds keyboard focus, and answers the URI. The pointer is not drawn.
- **`PickColor`** freezes the outputs and shows the same overlay with a magnifier around the pointer. A click answers the pixel in sRGB `(ddd)` and copies `#rrggbb` to the clipboard; Escape answers 1.
- **The files in flight** beneath the runtime directory are removed when they are older than one hour, at each new screenshot, and with the session.
- **The shell's entry points** reach this method through the public portal, never a private path: the Print key and the control center's tiles run `athanor-recorder` (PT13).

**PT9. ScreenCast.**

- **Sources.** `AvailableSourceTypes` is monitor and window (1 and 2). `AvailableCursorModes` is hidden and embedded (1 and 2); metadata (4) follows spike S1. Virtual monitors are excluded (PT15).
- **The picker.** `Start` opens one dialog transient for the application: a tab for screens, with each output's name and a still picture, and a tab for windows, with each toplevel's icon, title and still picture, taken through the capture code of `athanor-sulphur-client`. `multiple` allows several selections. Share and Cancel follow PT4; "Remember this choice" appears only when the application asked for `persist_mode` 1 or 2, unticked; ticked, it persists the choice for the mode the application asked for (decision 3).
- **Restore.** With `restore_data` of vendor `athanor`, version 1, a valid source and a granted persistence, `Start` shares without the picker. The data names a monitor by its make, model and serial, never by its connector, and a window by its application id; a source that cannot be found, or a window id matching more than one window, falls back to the picker. The frontend keeps the token in table `screencast`, and Settings revokes it.
- **The stream.** One PipeWire video node per source, produced by the backend: ext-image-copy-capture frames into shared-memory buffers in BGRx or BGRA, offered at the source's size and up to its output's refresh rate, paced by the compositor's frame events. Buffers in DMA-BUF follow spikes S1 and S2. `Start` answers the node ids, each with `source_type`, `size` and, for monitors, `position`. The frontend opens the PipeWire remote for the application, limited to those nodes (`src/screen-cast.c`).
- **A window shares its own picture,** never what covers it.
- **The session ends** when the application closes it, when the user stops it from the bar (PT10), when the shared window closes, or when the shared output disappears. The backend then emits `Closed` and removes the nodes.

**PT10. The private interface and the capture indicator.**

- **`os.athanor.Portal1`**, at `/os/athanor/Portal1`, under the additional bus name `os.athanor.Portal` on the backend's connection:
  - property `CaptureSessions`, `a(sssu)`: session id, application id, application name, kind (1 screen, 2 window, 3 screen and window);
  - method `StopCapture(s id)`;
  - property `SessionInhibitors`, `a(sssu)`: application id, name, reason, and the inhibited flags of PT11 that are not idle;
  - property `InputSessions`, `a(sss)`: session id, application id, application name, for each RemoteDesktop session whose EIS context in the compositor is open, from the compositor's answer to `ConnectToEIS` to `CloseSession` (PT15, *amended on 2026-11-17*). `StopCapture` also takes the id of such a session: it closes the session, and so revokes its file descriptor; when the compositor's `CloseSession` fails, it answers an error and the session stays open and listed (PT15) (*amended on 2026-11-17*);
  - `CaptureSessions` and `SessionInhibitors` emit `PropertiesChanged` with their values; `InputSessions` emits it as invalidated, without its value, so its application ids reach no other client of the session bus, and the bar reads it again with a call admitted as below (*amended on 2026-11-17*).
- **Admission.** Callers are admitted by their unit, as `athanor_unit::bus_caller::admit` checks a caller (`doc_session_daemons.md` SD5): through the pidfd the bus returns, the verified user systemd places the caller in exactly its unit, as that unit's main process, whose one `ExecStart` runs the unit's executable and whose unit files lie beneath `/usr/lib/systemd/user`; a bus that returns no pidfd is refused, and nothing is read under `/proc` (#1047) (*amended on 2026-11-17*). The units: `athanor-bar.service` (`CaptureSessions`, `InputSessions` and `StopCapture`), `athanor-shelld.service` (`CaptureSessions`, for do not disturb), `athanor-osd.service` (`SessionInhibitors`). Every other caller gets `AccessDenied`.
- **The indicator** (F-bar-17, and the screen-sharing part of F-bar-16) is a module of the bar, shown while `CaptureSessions` or `InputSessions` is not empty and hidden otherwise (BR3). Its icon is an Adwaita symbolic icon, and its colour is the visual language's to fix; its popover lists each session by the application's icon and name and what it shares ("Sharing your screen", "Sharing a window"), each with a Stop button that calls `StopCapture`. A session of `athanor-recorder` reads "Recording your screen". A session of `InputSessions` reads "Controlling your input", with its Stop button (*amended on 2026-11-17*). The bar's own module design belongs to `doc_bar.md` (section 3).
- **Do not disturb** (NC6, item 4): `athanor-shelld` reads `CaptureSessions`; a non-empty list is the screen-sharing trigger.

**PT11. Inhibit.**

- **`Inhibit`** records the application, the flags and `reason`, and holds the inhibition until `Close` on its request.
  - **Idle (8):** `org.freedesktop.ScreenSaver.Inhibit` on its owner, cosmic-idle until step 1 of `doc_session_daemons.md` SD22 and `athanor-idle` after it (SD5), released with `UnInhibit`. With no owner the request answers 2.
  - **Log out (1) and user switch (2):** listed in `SessionInhibitors`. `athanor-osd` lists them by name and reason in the log-out, restart and shut-down dialogs (OD18, as amended in section 3).
  - **Suspend (4):** it blocks automatic suspend only (decision 5): listed in `SessionInhibitors` and held through `os.athanor.Idle1.InhibitSuspend(app_id, reason)` of `athanor-idle`, released with `Uninhibit` (`doc_session_daemons.md` SD5): the suspend timer is removed and the blank is kept, so the screen still blanks and locks and automatic suspend does not happen; the user's own suspend is never blocked. Until step 1 of SD22 ships `athanor-idle`, the flag is held as an idle inhibition on cosmic-idle's `org.freedesktop.ScreenSaver`, which also stops the blank.
- **`CreateMonitor`** opens a session whose `StateChanged` gives `screensaver-active` from logind's `LockedHint` for the session (the lock sets it, lock decision) and `session-state` 1, running, always. `QueryEndResponse` is accepted and has no effect: the query-end phase is excluded (PT15).

**PT12. Background** (SW4).

- **`GetAppState`** answers, for each application id with a toplevel in `athanor-sulphur-client`'s model, 2 when one of its toplevels is activated and 1 otherwise. An application with no toplevel is absent, which the frontend reads as background (`src/background.c:241-276`). The match between a Flatpak's id and its toplevel's `app_id` is spike S4.
- **`RunningApplicationsChanged`** is emitted when that set changes, at most once a second.
- **`NotifyBackground`** sends a notification through `org.freedesktop.Notifications` (`athanor-shelld`): "<name> is running in the background", with the actions "Allow" (answer 1) and "Stop" (answer 0, after which the frontend ends the application and records the refusal, `src/background.c:457-490`). When the notification closes without an action the answer is 2, allow this once (decision 7).
- **What Software reads.** The frontend publishes what runs in the background as `BackgroundApps` on `org.freedesktop.background.Monitor` (`src/xdp-background-monitor.c:23-24`, 1.20.4), once a Background backend exists. That property is the interface SW4's Apps group needs (section 3).
- **`EnableAutostart`** is deprecated and no longer called by the frontend; it is not implemented.

**PT13. `athanor-recorder`, the shell's capture client.**

- **Three commands:**
  - `athanor-recorder screenshot`: an interactive `Screenshot` through the public portal; the recorder copies the result from the backend's runtime directory (a read its Landlock allows, PT3) to `$XDG_PICTURES_DIR/Screenshots/Screenshot from <date and time>.png`, and the original stays for the sweep of PT8; a notification "Screenshot saved" offers "Show in Files" (`org.freedesktop.FileManager1.ShowItems`, FM16).
  - `athanor-recorder pick-color`: `PickColor`, then a notification "Colour copied" with the value.
  - `athanor-recorder record`: a ScreenCast session (monitor or window, cursor embedded, no persistence), the portal's picker, then a GStreamer pipeline from `pipewiresrc` to `$XDG_VIDEOS_DIR/Screencasts/Screencast from <date and time>.webm`: VP8 in WebM, video only (decision 4). When the session closes, from the bar's Stop or for any other reason, the pipeline ends cleanly and a notification "Recording saved" offers "Show in Files". A full disk ends the recording with the file playable up to that point and a notification saying so.
- **One recording at a time.** While recording the program owns `os.athanor.Recorder` on the session bus; a second `record` asks it to stop instead, so the control center's tile toggles.
- **Identity.** It registers `os.athanor.Recorder` through `org.freedesktop.host.portal.Registry` before its first call, and ships `os.athanor.Recorder.desktop` with `NoDisplay=true`, so dialogs and the indicator name it.

**PT15. Exclusions,** each with its reason.

- **Wallpaper portal:** the wallpaper belongs to the visual language and Settings; no default application sets it.
- **GlobalShortcuts, InputCapture, Clipboard:** each grants input or clipboard control to an application and needs its own threat model; none is needed by a default application.
- **RemoteDesktop, no longer excluded** (*amended on 2026-11-17*, section 6, decision 11; `doc_own_stack.md` decision 33, wave 2c, amended on 2026-11-17). The backend serves `org.freedesktop.impl.portal.RemoteDesktop` from step 7 of PT18. InputCapture stays excluded, with an amendment of its own later. Its design and its threat model, against the tiers of `doc_threat_model.md`:
  - **The session.** The backend serves version 2 of `org.freedesktop.impl.portal.RemoteDesktop`, the version that has `ConnectToEIS` (*amended on 2026-11-17*). Input reaches the compositor only through libei. After `Start` has answered, the frontend calls the impl's `ConnectToEIS` for the session; the backend then obtains one EIS file descriptor from the compositor's `os.athanor.Eis1.ConnectToEIS` and answers it. A refusal by the compositor (a `device_types` of 0 or with an unknown bit among them) is the error of the impl's `ConnectToEIS`: the application gets no file descriptor, and `Start`, already answered, is not changed. A second `ConnectToEIS` for the same session is refused. When the session closes, from `Close` or for any other reason, the backend calls `os.athanor.Eis1.CloseSession`. When the owner check fails at a close other than `StopCapture`, the backend sends no `CloseSession` and writes one journal line, and relies on the revocation below: a process that is not the compositor holds no context, and the compositor ends every context when the backend's bus name changes owner (*amended on 2026-11-17*). On that path a `CloseSession` that answers an error, or is not answered within 2 s, is one journal line as well, and the session is ended all the same (*amended on 2026-11-17*). A `ConnectToEIS` that fails, by a compositor refusal, an owner check that fails or a call not answered within 2 s, spends the session: the session obtains no file descriptor later (*amended on 2026-11-17*). A `ConnectToEIS` that got no answer within 2 s, failed on the way, or was answered without a file descriptor may have left a context open: while the spent session still holds its handle, the backend calls `os.athanor.Eis1.CloseSession` for it once, and a failure of that call is one journal line; an error answer of the compositor leaves no context and is followed by no `CloseSession` (*amended on 2026-11-18*). Before the dialog, and again before each call to `os.athanor.Eis1` (`ConnectToEIS` and `CloseSession`), the backend reads the owner of `os.athanor.Eis` anew and admits it as the compositor by its unit, as `athanor_unit::bus_caller` admits a caller (`doc_session_daemons.md` SD5): through the pidfd the bus returns, the verified user systemd places it by `GetUnitByPIDFD` in exactly `athanor-sulphur.service`, as that unit's main process, whose one `ExecStart` runs `/usr/bin/athanor-sulphur` and whose unit file and drop-ins lie beneath `/usr/lib/systemd/user`. A bus that returns no pidfd is refused, and nothing is read under `/proc` (#1047) (*amended on 2026-11-17*). With no owner, as in cosmic-comp's session, or with any other owner, `Start` is refused without a dialog. The check needs the installed unit and path, so on the shell rig, in a dev build and with a compositor started outside `athanor-sulphur.service` it refuses `Start` by design (it fails closed); the positive path runs on athanor-ref alone. The backend refuses every `Notify*` method of the interface with a D-Bus error, since input reaches the compositor only through EIS, and refuses every call of the ScreenCast interface made on a RemoteDesktop session's handle, so a RemoteDesktop session carries no screen.
  - **The cap on sessions** (*amended on 2026-11-21*, maintainer decision, 2026-11-21). The backend holds at most 8 RemoteDesktop sessions for one owner, the application named by the `app_id` of `CreateSession`, counted from the answer to `CreateSession` until the session is closed. A ninth `CreateSession` for the same owner is refused with response 2, and the journal names the limit, and no session, dialog or EIS context is created for it; nothing is dropped silently, neither the request nor an earlier session of the owner. The cap is per owner, so the eight sessions of one application with an `app_id` never refuse another application's first; host applications that did not register have an empty `app_id` and share one owner. A session left listed by a frontend that died without `Close` counts against its owner until `StopCapture` closes it or the backend ends. The reason is that every session may hold an EIS socket of the compositor and the memory of its state, and one client that opens sessions without closing them must not exhaust the sockets or the memory that every other application and the compositor share. A session that closes frees its place at once.
  - **Consent, for each session.** `Start` shows a dialog of the backend, a window of Sal beside those of PT2 (*amended on 2026-11-17*), under the rules of PT4: the application's name and icon, the device types it asked for in `SelectDevices` (keyboard, pointer, touch screen), each granted or not by the user, the grant button insensitive for its first 500 ms and until at least one device type is ticked, so that granting nothing is the refusal (answer 1) and `Start` never answers `devices` as 0, the refusing button the keyboard default. `Start` answers the granted types as `devices`. The backend calls `os.athanor.Eis1.ConnectToEIS` only for a session the user has granted, with those types, and the compositor offers that session no device of another type. No consent is kept: the restore data of PT9 is ScreenCast's alone, so the backend does not honour `persist_mode`, answers no restore data, and every session asks again.
  - **The assets.** Input to every client of the session: a granted application types, points and touches as the user does.
  - **A confined application that asks the portal** (tier 2, TM2) gets a session only after the user's consent in the dialog, for that session alone. It reaches the backend only through the frontend, which the frontend-only rule of PT3 enforces, and the compositor hands the file descriptor only to the backend.
  - **A process that impersonates the backend** to obtain a file descriptor without a dialog. The compositor admits, at every call, only the owner of `org.freedesktop.impl.portal.desktop.athanor` that the same rule places, through its pidfd, in exactly `xdg-desktop-portal-athanor.service`, as that unit's main process, whose one `ExecStart` runs `/usr/libexec/xdg-desktop-portal-athanor`; it reads nothing under `/proc` (#1047) (*amended on 2026-11-17*). This holds against tier 2, which owns no bus name outside its filter and has no unit manager (TM2). Against tier 1 it is an integrity check, not a barrier (TM1): unconfined code can start a unit of that name, or own `os.athanor.Eis` before the compositor does, and it is the user.
  - **Revocation.** The compositor ends the file descriptor's context when the backend calls `CloseSession` for the session (*amended on 2026-11-17*), when the backend's bus name changes owner, and when the backend exits, so no file descriptor outlives the session or the backend that asked for it. The backend sends no `CloseSession` when it ends itself: the change of owner of its bus name revokes every context it held (*amended on 2026-11-17*). The compositor shuts down its end of the socket, so the application's file descriptor reads end of stream; the touches the context holds end with their own `up`, so a touch of the user is never cancelled.
  - **The lock and the paused session.** From the lock request on until the unlock, and while the session is paused on another virtual terminal, the compositor drops the events of every context, releases the keys, buttons and touches they hold, the touches cancelled, and delivers nothing, so a session neither types into the lock surface nor acts behind it or where the user cannot see.
  - **Clients only.** Injected input reaches Wayland clients only, never a compositor binding, Orca's keyboard monitor (`doc_accessibility.md` AX4) or the keyboard aids (AX11). An injected protected key of `doc_own_stack.md` decision 30 is dropped and reaches neither the compositor nor any client: a session switches no workspace, suspends no inhibitor with Ctrl+Alt+Tab and shows no reveal key. Injected keys keep their own modifier and xkb state, apart from the seat's physical state: an injected modifier never changes what a physical key means, and a physical modifier never makes an injected key a binding or a protected chord. An injected key that reaches a client still cancels a pending tap of Super, as a hardware key and an injected button or touch do, so a physical Super released after it opens no launcher; the injected key itself reaches only the client, and a key that reaches no client cancels nothing (maintainer decisions, 2026-11-17; `doc_own_stack.md` decision 33, wave 2c) (*amended on 2026-11-17*).
  - **The backend's own dialogs** (*amended on 2026-11-17*). Injected input never reaches a surface of `xdg-desktop-portal-athanor`, the consent dialog or any other, which the compositor identifies by the identity it reads for every Wayland client when the client connects (`doc_own_stack.md` OS4; `identify` in Sulphur's `identity.rs`): the peer's pidfd from `SO_PEERPIDFD`, then, through its pid, its executable `/usr/libexec/xdg-desktop-portal-athanor` and the unit of its cgroup, `xdg-desktop-portal-athanor.service`. The privileged-clients list has no line for it (*amended on 2026-11-17*). So a session cannot Tab through the consent dialog of a second session and widen its own grant. Every dialog of the backend is a surface of the backend's one process, the process the compositor identifies, and no helper process opens one.
  - **The indicator.** While the compositor's EIS context for a session is open, from its answer to `ConnectToEIS` to `CloseSession`, the session is listed in `InputSessions` (PT10) and the bar's capture indicator shows it; its Stop closes the session and calls `CloseSession`, which revokes the file descriptor. When that `CloseSession` fails, by the owner check, a timeout or an error of the call, `StopCapture` answers an error and the session stays open and listed, so the indicator and its Stop remain until a `CloseSession` succeeds or the compositor revokes the context (*amended on 2026-11-17*). A frontend that dies without `Close` leaves the session listed until Stop or the backend's own end of the session, which is the safe direction.
  - **Residual risk.** Within a granted session the application acts on every client as the user at the keyboard would, a terminal and a polkit prompt included, but not the backend's own dialogs, which never take injected input (above). A remote session therefore cannot operate any surface of the backend, the file chooser, the share picker and the screenshot overlay included, by design. The consent given for each session is the boundary. A close other than `StopCapture` whose owner check fails, even for a moment, as a check not answered within 2 s does, or whose `CloseSession` answers an error or is not answered in time, removes the session from `InputSessions`, so the indicator no longer shows it, while the compositor's context and the application's file descriptor stay live until a revocation above ends them, at the latest when the backend's bus name changes owner (*amended on 2026-11-17*).

## 6. Decisions taken

Decided by the maintainer on 2026-10-05, each as the draft recommended.

1. **Who serves the GNOME settings keys** (PT5). Athanor's backend alone, `Settings=athanor`, serving the GNOME schemas generically through gio beside the appearance. Reason: AX2, LN15 and VL5 become this document's own guarantee, and the frontend gets no second `SettingChanged` from xdg-desktop-portal-gtk's mirror-derived `color-scheme` and `contrast`.
2. **One backend process** (PT2). D-Bus, the PipeWire producer, the GTK dialogs and the Sal consent window of PT15 in one process under one Landlock ruleset; the Sal window runs on a thread of its own, with its own Wayland connection, and is to take its parent through `zxdg_importer_v2` as the GTK dialogs do (PT4), an import Sal does not have yet and step 7 of PT18 adds (*amended on 2026-11-17*). Reason: untrusted content is already parsed outside (`athanor-preview-render`), and both halves would need the same read access and the same privileged Wayland globals, so a split adds an interface without narrowing what an attacker reaches.
3. **Remembered screen-sharing choices** (PT9). `persist_mode` 1 and 2 are honoured behind a "Remember this choice" box, unticked by default; tokens are revocable in Settings. Reason: the choice stays the user's, and the indicator shows every session, asked or restored.
4. **The recorder's format** (PT13). VP8 in WebM, video only. Reason: `vp8enc` is already in Fedora's gstreamer1-plugins-good 1.26.11, the file plays everywhere, and audio capture raises a consent question this document does not settle. Spike S7 measures the load.
5. **An application's suspend inhibition** (PT11). It blocks automatic suspend only; the user's own suspend is never blocked. Reason: an application may stop the machine from suspending under its work, not stop a person who chose to suspend.
6. **The dialogs left to xdg-desktop-portal-gtk** (PT1). AppChooser, Print, Account, Email, DynamicLauncher and Notification forwarding stay with gtk in the first release. Reason: they work today and receive the appearance through GSettings; AppChooser is the first candidate for a later revision.
7. **A background notice nobody answers** (PT12). The application runs this once (answer 2). Reason: nothing a person did not see is ended, the frontend asks again at the next start, and Software's page shows it running meanwhile.

Decided by the maintainer on 2026-10-08, each as the review recommended.

8. **Scope budget** (PT2). The "why not upstream" paragraph and the owner are part of this document, and the decision of 2026-10-04, "Athanor writes its own, real portal backend", stands. Reason: the rule of A2-14 was written after the first draft.
9. **Approval of PT18** (PT18, section 4). All seven steps are approved together. Reason: a failed spike returns its rule to the maintainer and each step merges on its own.
10. **The accepted risk of PT3.** One process with the main socket and read access to `$HOME`, as decision 2 chose.

Decided by the maintainer on 2026-11-17.

11. **RemoteDesktop first, through libei** (PT1, PT15, PT18 step 7). The backend serves RemoteDesktop through the compositor's libei sender contexts, behind its own consent dialog, asked for each session before the file descriptor is requested; the compositor hands that file descriptor over the session bus only to the backend's unit and executable, revokes it with the session, pauses it while the session is locked, and delivers its input to clients only (`doc_own_stack.md` decision 33, wave 2c). InputCapture stays excluded, with an amendment of its own later.
12. **What a remote session may reach** (PT10, PT15). An injected protected key of `doc_own_stack.md` decision 30 is dropped; Orca's keyboard monitor and the keyboard aids never see injected keys; the bar's capture indicator shows each open session with a Stop button that revokes it; the devices also pause, with held input released, while the session is paused on another virtual terminal; the compositor offers only the device types the user granted in the dialog; and the backend's own dialogs never take injected input, so a session cannot widen its grant through another session's consent dialog.
13. **How the backend and the compositor know each other, and the dialog** (PT2, PT10, PT15, PT18 step 7; 2026-11-17). Each admits the other by its systemd unit, through the pidfd the bus returns, as `athanor_unit::bus_caller` checks a caller, and never reads `/proc` (#1047): a confined unit cannot read another process's executable there. The backend's own end sends no `CloseSession`, since the compositor revokes every context when the backend's bus name changes owner. `InputSessions` is announced as invalidated, so application ids are not broadcast. The consent dialog is drawn with Sal. RemoteDesktop is routed to the backend only after BR3's indicator with its Stop and #1131 have merged. A failed `ConnectToEIS` spends its session. When the owner check fails at a close other than `StopCapture`, no `CloseSession` is sent, one journal line is written and the revocation covers it; a `StopCapture` whose `CloseSession` fails answers an error and keeps the session listed, so the indicator and its Stop remain until a `CloseSession` succeeds or the compositor revokes the context. The backend serves version 2 of `org.freedesktop.impl.portal.RemoteDesktop`. The bar is admitted to `os.athanor.Portal1` by `athanor_unit::bus_caller::admit`. The Sal consent window runs in the backend's process on a thread of its own, beside the GTK main thread, each toolkit with its own Wayland connection, its parent to be imported through `zxdg_importer_v2` as PT4 imports the GTK dialogs', an import step 7 adds to Sal. An injected key that reaches a client cancels a pending tap of Super, as a hardware key and an injected button or touch do, and still reaches only the client; one that reaches no client cancels nothing. The compositor admits the backend in `doc_own_stack.md` decision 33 by the same `bus_caller` rule.
