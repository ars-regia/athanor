# Athanor Settings

Status: **revision 1 draft, 2026-10-05: the maintainer's decisions applied; text not yet reviewed.** It is the specification that `doc_shell.md` (SH3, stage 6) and `doc_shell_standard.md` (ST1) require for the Settings application. It designs the program, its window and pages, which preference each page writes and through which owner's interface, how the program is started and confined, how it replaces cosmic-settings, the tests and the order of construction. It designs pages, not preferences: every store named here belongs to another document or to an upstream service, and this one only says which of its keys Settings writes.

## 2. Decisions

**SE1. One application, and what it is not.**

- Settings is one libadwaita application, application id `os.athanor.Settings` (`doc_naming.md` rule 18; the desktop entry name already exists, `doc_files.md:237`). It covers the register's Settings entries except the exclusions of SE24.
- It holds no preference of its own beyond its window state. Every value it shows is read from the owner's store or interface, and every change goes back through it. When an owner's daemon is absent, the page says so and offers nothing; it never writes a fallback file.
- It is not the control center: a quick toggle stays in the panel (CC4). It is not the place for updates: system updates stay in the shield and in Software (SW16), and Settings has no updates page.

**SE2. Programs and crates.**

- **`forge/specs/athanor-settings`**, a new binary crate: the window, the pages and their widgets, on `libadwaita` (libadwaita 1.8.8 and GTK 4.20.4 in the image, `rpm -q`, 2026-10-05). One crate for the program (SH4).
- **`system/athanor-settings-core`**, a new library with no GTK type: the page registry and its search keywords, the deep-link grammar (SE4), the table of writable keys (SE7), the validation of every value before it is written, the display-revert state machine (SE12) and the shortcut-conflict check (SE15). Its tests run without a display.
- **Models** come from `athanor-services` (CC2): network, Bluetooth, audio, battery, power profile, brightness, and the udisks model that `doc_disks.md` owns there. Settings adds no D-Bus model of its own for these services.
- **Detail widgets** come from `athanor-controls` (CC5) where the control center already has them: Network, Bluetooth, Audio, Display (brightness, night light, display mode) and Battery. A Settings page embeds that widget and adds what the panel does not offer, so each control keeps one implementation. The widgets carry no stylesheet of their own; in Settings they take libadwaita's.
- **Owners' writers** are called, never re-implemented: `athanor_style` for appearance (VL4), `athanor_compositor_client` for every COSMIC store (SH2), `athanor_layout` for the layout document, `athanor_i18n` for the language list (LN4). The interfaces this needs from them are in section 3.
- **`athanor-settings-rs` is mined, not revived** (SH3): its page list and strings are read for coverage, no code is moved. It leaves the workspace and the tree in step 1 of SE26, so that one application id has one program.
- Translations through `gettext-rs` 0.8.0 with the `gettext-system` feature, as for every libadwaita application of ours (LN1, `doc_languages.md` decision 1). `panic = "abort"` as everywhere: a panic ends the process, and systemd restarts it (SE5).

**SE3. The window.**

- An `AdwApplicationWindow` with an `AdwNavigationSplitView`: a sidebar of pages in groups, the page on the right; below 600 logical pixels the split view collapses into one column, as libadwaita does.
- **Groups and pages:** Connections (Network, Bluetooth); Device (Displays, Sound, Power, Keyboard, Mouse and Touchpad); Personalisation (Appearance, Wallpaper, Desktop); Notifications; Accessibility; System (Language and Region, Date and Time, Users, Privacy and Security, Search, Default Applications, Firmware, About). A page whose service or hardware is absent is not listed (Bluetooth without an adapter, Firmware without fwupd), as BR3 does for the bar.
- **Search** at the top of the sidebar matches page titles, section titles and translated keywords from the registry of `athanor-settings-core`, and opens the section, not only the page.
- **The landing page** (F-settings-32) is what the window shows when opened without a page: the user's card (avatar and full name from AccountsService, opening Users), the device card (pretty hostname, model, Athanor version, opening About) and the groups as rows. It shows nothing that needs a privileged read.
- Every page follows ST7: reached and operated from the keyboard alone, every control named for AT-SPI, right-to-left mirrored by GTK, strings through gettext.

**SE4. How Settings is opened, and its unit.**

- **The unit.** Settings runs only in the user unit `athanor-settings.service`. This is the unit name `doc_notification_center.md` NC8 admits for its Settings methods.
- **The interface.** Settings owns the bus name `os.athanor.Settings1` with one method, `Show(s target)`, and installs `/usr/share/dbus-1/services/os.athanor.Settings1.service` with `SystemdService=athanor-settings.service`, so D-Bus activation always starts the unit (LA8). `Show` raises the window, or opens it, at the target.
- **The target** is `""` for the landing page, a page id, or a page id and a section id joined by `/`. Page ids: `network`, `bluetooth`, `displays`, `sound`, `power`, `keyboard`, `mouse`, `appearance`, `wallpaper`, `desktop`, `notifications`, `accessibility`, `region`, `datetime`, `users`, `privacy`, `search`, `default-apps`, `firmware`, `about`. The sections each page offers are listed in the registry and are a stable interface: `notifications/schedule`, `privacy/developer-mode`, `users/fingerprint`, `displays/mode`, `power/idle` and every section named in this document. An unknown target opens the landing page and writes one journal line.
- **The desktop entry** `os.athanor.Settings.desktop` has `Exec=athanor-settings` and `Keywords` for the launcher. When the binary starts outside `athanor-settings.service` (read from `/proc/self/cgroup`), as the bar's transient application unit of BR2 or a command line in a shortcut does, it initialises no GTK, calls `Show` with its `--show=<target>` argument or `""`, and exits 0. The window therefore never runs on a security-context socket or outside its unit.
- **Callers:** the control center's footer and tiles (CC4, at the page of the tile), the notification center's two links (NC11: `notifications/schedule` and `notifications`), Software's link to the developer switch (`privacy/developer-mode`), the lock's prompt to enrol a finger, if that document adds one (`users/fingerprint`), and `DisplayToggle` (SE12).

**SE5. Lifetime.** Decision 1 (section 6).

- `athanor-settings.service` is started on the first `Show` and stays resident until logout. Closing the window destroys the window and its pages; the process keeps its connections and the registry, so the next `Show` builds one page, not the application.
- `Restart=on-failure`, `RestartSec=200ms`. The current target is written to `$XDG_RUNTIME_DIR/athanor-settings/state` on every navigation; a restarted Settings whose state says a window was open reopens it at that target within 1 s (ST5 recovery).
- **Memory budget** (ST5, a ceiling chosen here and measured at step 5 of SE26): 40 MB proportional set size with no window, 150 MB with the window open on any page.

**SE6. Confinement.**

- **Landlock at start,** before GTK and before the Tokio thread of CC3 create any thread, refusing to continue when more than one thread exists or the kernel has no Landlock, as `athanor-layout-chooser` does (`src/sandbox.rs`). Writes are allowed only beneath:
  - `$XDG_RUNTIME_DIR/dconf` (the shared-memory file every GSettings client writes; the database itself is written by `dconf-service` over D-Bus);
  - `$XDG_RUNTIME_DIR/athanor-settings` (window state, the display-revert state of SE12, the scaled avatar of SE20);
  - `$XDG_CONFIG_HOME/athanor` (the layout document through `athanor-layout`, `software.toml` of SW2);
  - `$XDG_CONFIG_HOME/cosmic`, written only through `athanor-compositor-client` (SH2);
  - `$XDG_DATA_HOME/backgrounds` (the copies of the user's own wallpapers, SE13);
  - `$XDG_CONFIG_HOME/autostart` (the user's startup entries, SD10);
  - `$XDG_CACHE_HOME`, and `/dev/dri` for rendering, as the layout chooser grants;
  - the user's `mimeapps.list`, in the form spike SE-S4 settles (section 4).
- **Landlock network rules (ABI 4)** refuse every TCP bind and connect; the unit adds `RestrictAddressFamilies=AF_UNIX`. Settings speaks only to local services; NetworkManager, fwupd's own client (SE22) and the others do the network.
- **The unit:** `NoNewPrivileges=yes`, `ProtectSystem=strict`, `PrivateTmp=yes`, `ProtectKernelTunables=yes`, `ProtectKernelModules=yes`, `ProtectControlGroups=yes`, `RestrictNamespaces=yes`, `LockPersonality=yes`, `MemoryDenyWriteExecute=no` (GTK's renderers may need executable mappings for shaders on some drivers; section 4, item 8), `SystemCallFilter=@system-service`, `MemoryHigh=` and `MemoryMax=` from the budget of SE5. `NoNewPrivileges=yes` means no setuid program can run from Settings: no `pkexec`, no `passwd`.
- **The Wayland socket:** Settings connects on cosmic-comp's main socket, without a security context, because two of its pages need protocols cosmic-comp offers only there (decision 2, section 6). Settings follows the per-surface confinement of SH2 when it gives every shell surface a narrower socket.

No setuid program, no polkit rule is written by this document. The one new system unit is `athanor-passwd@` (SE20, decision 4).

That makes "the Accessibility page writes these keys and no others" (`doc_accessibility.md` AX2) a test, not a promise.
- **Time-zone, hostname and system-locale changes ask an administrator.** cosmic-settings.rules waived that for `wheel`; it leaves with cosmic-settings (SE23), and this document does not replace it. LN5 already restored `auth_admin_keep` for localed.

**SE9. Network and Bluetooth.**

- The pages embed the `athanor-controls` Network and Bluetooth pages (CC5) and add: the list of saved connections with their details (IP settings, DNS, metered, auto-connect, forget), the creation of wired, Wi-Fi (hidden networks included) and WireGuard connections, which NetworkManager supports without a plugin, the import of a WireGuard file chosen through the portal file chooser, a hotspot, and the proxy (`org.gnome.system.proxy` `mode`, the manual hosts and the automatic URL, which GIO's proxy resolver reads through glib-networking 2.80.1 and libproxy 0.5.12, installed).
- **Mobile broadband** (F-settings-03) is a section of Network shown only when ModemManager (1.24.2, installed) reports a modem: enable, APN, PIN unlock, roaming. It goes through NetworkManager's GSM connections; ModemManager's `Device.Control` is `yes` for the active session (2026-10-05), so the rule cosmic-settings shipped for it is not needed.
- **VPNs that need a NetworkManager plugin** (OpenVPN, OpenConnect) are not offered: no plugin is in the image (`rpm -q NetworkManager-openvpn NetworkManager-openconnect`, not installed, 2026-10-05). Adding one is a package decision of `doc_software.md`, not of this page.
- **Pairing** uses the BlueZ agent of `athanor-services` (section 3): a PIN or passkey request shows in Settings while the page is open and in the panel otherwise. Settings registers no agent of its own.
- Airplane mode stays a tile of the panel (CC4); Settings shows its state and does not duplicate the switch.

**SE10. Sound.** The page embeds the `athanor-controls` Audio page (outputs, inputs, volumes, per-application streams) and adds the card profile of each device, the balance, `org.gnome.desktop.sound event-sounds` and `theme-name` (the sound theme NC7 plays from), and `allow-volume-above-100-percent`. The headset dialog of `athanor-osd` regains its "Sound settings" button, which calls `Show("sound")`, in the step where Settings ships (OD19, controller ruling of 2026-10-05; section 3).

**SE11. Power, battery and idle.**

- The page embeds the `athanor-controls` Battery page (health, charge limit through UPower, CC5) and the power profile.
- **Blank and suspend** (section `power/idle`, F-settings-21, LP5, `doc_lock_and_prompts.md:80`): "Blank screen after" (1, 2, 3, 5, 10, 15, 30 minutes, never), "Suspend after, on battery" and "Suspend after, plugged in" (15, 20, 30, 45, 60, 90 minutes, never). The battery row shows only on a machine with a battery. The factory values are D6's: 5 minutes, 15 minutes on battery, never plugged in; they are not written by Settings but shipped as the defaults of `org.athanor.desktop.idle` from step 1 of SD22 (LP5). Before that step the page shows cosmic-idle's store, which on a fresh account holds cosmic-idle's compiled values.
- **The lock follows the blank.** The page says "The screen locks when it blanks" and offers no separate lock timer, because LP5 keeps one idle policy and the idle daemon locks 500 ms after blanking (cosmic-idle until step 1 of `doc_session_daemons.md` SD22, then `athanor-idle`, SD4).
- **Until step 1 of the session-daemons construction (`doc_session_daemons.md` SD22)** the store is cosmic-idle's `com.system76.CosmicIdle` version 1: `screen_off_time`, `suspend_on_battery_time`, `suspend_on_ac_time`, in milliseconds, `None` for never (key names found in `/usr/bin/cosmic-idle`, cosmic-idle 1.8.0, `strings`, 2026-10-05). Settings writes them only through `athanor_compositor_client::idle` (section 3). From that step the store is `org.athanor.desktop.idle` (`blank-after`, `suspend-after-battery` and `suspend-after-ac`, in seconds, 0 for never, SD3), which Settings writes through GIO, and `athanor_compositor_client::idle` is deleted in the same change; the page changes its writer and nothing else.
- Lid and power-button actions stay logind's system configuration; Settings does not edit `/etc/systemd/logind.conf` (SE24).

**SE12. Displays.**

- **Arrangement, resolution, refresh rate, scale, rotation, enable, mirroring and variable refresh** are applied through output management in `athanor-compositor-client` (section 3). cosmic-comp 1.8.0 offers its output-configuration globals only to clients without a sandboxing security context (`OutputConfigurationState::new(dh, handle.clone(), client_not_sandboxed)`, `src/state.rs:677` of the cosmic-comp epoch-1.8.0 source, 2026-10-05), which is why SE6 places Settings on the main socket. cosmic-comp itself persists the result in `$XDG_STATE_HOME/cosmic-comp/outputs.ron` (`src/config/mod.rs:342`); Settings writes no output file. Which of these attributes the protocols carry in 1.8.0 (the primary output, mirroring, variable refresh) is spike SE-S2.
- **Keep or revert.** After an apply that changes resolution, refresh, scale, rotation or the set of enabled outputs, a dialog asks "Keep these display settings?" with a 15-second countdown and "Revert" focused; on Revert, on the countdown's end or on Escape, Settings applies the previous configuration. The previous configuration and the deadline are written to `$XDG_RUNTIME_DIR/athanor-settings/display-revert` before the apply, so a Settings restarted after a crash (SE5) still reverts on time. The state machine lives in `athanor-settings-core` and is tested there.
- **Identify** shows the outputs' numbers through `os.athanor.Osd1.IdentifyOutputs()` and removes them with `DismissOutputIdentifiers()` (OD19): the arrangement shows the same numbers. Until `athanor-osd` ships (stage 4), the button is absent.
- **Night light, brightness of external monitors and display mode** are the `athanor-controls` Display page (CC5), embedded; their mechanisms are the control center's spikes S1, S4 and S5. Night light has a manual schedule only (SE24).
- **`DisplayToggle`** (OD14): Settings binds the action, still without a default key, to `athanor-settings --show=displays/mode` through `athanor_compositor_client::shortcuts::set_system_action` (`shortcuts.rs:61`), so a key the user assigns opens the display-mode section.

**SE13. Appearance and wallpaper.**

- **Appearance** writes the five keys of VL4 only through the apply function of `athanor-style`: colour scheme (light, dark), contrast (normal, high), accent mode (fixed, from the wallpaper) and the nine fixed accents. It never writes the GNOME mirrors or `CosmicTheme` itself (VL4). With the hearth wallpaper the page shows "from the wallpaper" as unavailable, since the mode behaves as fixed (VL3).
- **Type:** no font-family choice. The system font is Adwaita Sans 11 (VL6); text size is the "Large text" switch of the Accessibility page (AX2), not a second control here.
- **Wallpaper** offers the hearth (`/usr/share/backgrounds/athanor/`, one entry that follows the accent and the scheme, VL8), the other images of `/usr/share/backgrounds`, and the user's own images, chosen through the portal file chooser and copied into `$XDG_DATA_HOME/backgrounds`, so the wallpaper outlives the portal's grant. One image for all outputs, or one per output.

**SE22. Search, default applications, firmware and About.**

  - **Reading** needs no authorisation. The page reads `org.freedesktop.fwupd` on the system bus, object `/`: `GetDevices`, `GetUpgrades` for each updatable device, `GetRemotes` for the date of the last metadata refresh, the properties `Status` and `Percentage`, and the signals `Changed`, `DeviceAdded`, `DeviceRemoved`, `DeviceChanged` and `DeviceRequest` (fwupd 2.0.20, `/usr/share/dbus-1/interfaces/org.freedesktop.fwupd.xml`). So "Update" starts fwupd's own client, `fwupdmgr update <device-id> --assume-yes --no-reboot-check`, as a transient user unit, and follows it by the unit's state and fwupd's signals; "Refresh" runs `fwupdmgr refresh` the same way. The client downloads the cabinet the signed metadata names, checks its checksum and calls `Install`.
  - **Authorisation** is fwupd's own polkit actions (`/usr/share/polkit-1/actions/org.freedesktop.fwupd.policy`, fwupd 2.0.20): `org.freedesktop.fwupd.update-internal-trusted` and `update-hotplug-trusted`, used for a cabinet signed by a key fwupd trusts, are `yes` for the active local session, so such an update installs without a password; `update-internal` and `update-hotplug`, for any other cabinet, are `auth_admin_keep`. The defaults are fwupd's and are kept, as `doc_disks.md` decision 5 keeps udisks's. The page offers no downgrade (`downgrade-*`), no BIOS settings and no host-security fixes.
  - An update that needs a restart says so on the page; the restart is the session menu's.

The image's update state is not shown: it lives in the shield (SW16).

## 6. Decisions taken

Taken by the maintainer on 2026-10-05. Each followed the recommendation of revision 0.

1. **Is Settings resident?** (SE5) Choice: started on the first `Show`, resident until logout. Reason: it meets ST5's 100 ms for every opening after the first and the recovery threshold, pays memory only for users who opened Settings once, and needs no exception to the standard (a cold GTK4 start misses 100 ms, `doc_control_center.md:38`).
2. **Which Wayland socket?** (SE6, SE12, SE18) Choice: the main socket for the whole application in release 1. Reason: cosmic-comp offers output configuration and the accessibility manager only there; Landlock, no network and no setuid already limit a compromise, and every privileged client of ours uses the same socket until SH2's per-surface confinement narrows them all.
3. **The system disk passphrase** (SE21; DK6; `doc_kernel_profile.md` D42). Choice: change of passphrase now through udisks `ChangePassphrase` (`auth_admin_keep`); keyslots (TPM, PIN, recovery key) wait for P4b. Reason: every user may need it, and udisks does it under an administrator's authorisation without new code touching key material; the TPM policy waits for D42's design.
4. **How a user changes their own password** (SE20). Choice: `athanor-passwd@`, a confined root service with PAM's `chauthtok`; until it ships the page points to `passwd`. Its implementation plan needs the maintainer's approval before any code. Reason: the only option that asks for the current password and works for a user outside `wheel`, on the model approved for the lock (D1).
5. **How far the Users page manages other accounts** (SE20). Choice: administrators create and delete accounts through AccountsService, the initial password hashed with yescrypt; no parental controls. Reason: shared machines need it, AccountsService does it under the right authorisation, and the hash comes from the system's own library.
6. **Does the Desktop page replace `athanor-layout-chooser`?** (SE14, SE23) Choice: yes; the chooser and `os.athanor.Layout` leave at the retirement step. Reason: one place for the layout, one program and one package fewer.
7. **Where firmware updates live** (SE22). Choice: a Firmware page built on fwupd's own D-Bus API, client and polkit actions, with no Athanor daemon (revised by the maintainer on 2026-10-05: revision 1 applied through `os.athanor.Lvfs`, whose daemon left the image on 2026-09-30, could not own its bus name and reported success whether or not anything was installed, `experimental/EXEMPT:42-47`). Reason: fwupd is in the image and already covers firmware; a Settings page must not rest on a daemon that is out of the image; and the shield and Software stay untouched.
8. **The exclusions of SE24.** Choice: as written, printers excluded. Reason: each excluded entry belongs to another document, needs a package and a design the image lacks, or is configured in its own application; driverless printers work without a page.
