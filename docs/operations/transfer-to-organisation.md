# Transfer to an organisation

| Field      | Value                                                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purpose    | How the repository moves from the personal account `hr-mes` to the organisation `athanor-os`, and what a later rename of the organisation costs         |
| Owner      | the maintainer (`@hr-mes`)                                                                                                                              |
| Status     | revision 1, 2026-10-06. The maintainer chose the name `athanor-os`. Lines marked _(to verify)_ are GitHub behaviour not yet observed on this repository |
| Depends on | [secrets.md](secrets.md) (SEC, ENV, KC4), [github-settings.md](github-settings.md)                                                                      |
| Defines    | TO1 to TO8                                                                                                                                              |

The pipeline derives the registry owner from `GITHUB_REPOSITORY_OWNER` and `REGISTRY_HOST`
(`scripts/verify.py registry` enforces it, `system/Containerfile` and `flake.nix` included), and
the package janitors ask GitHub whether the owner is a user or an organisation. What still
names `hr-mes` is content: the URLs a shipped file points at, documentation, and the defaults of
scripts run outside Actions. Those change in one pull request after the transfer (TO4).

## 1. What the transfer does

| Id  | Item                                                                | After the transfer                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TO1.1 | Code, history, issues, pull requests, releases, Actions history     | Move with the repository. `github.com/hr-mes/athanor` and its git remote redirect to `github.com/athanor-os/athanor` as long as no new repository named `athanor` is created under `hr-mes`.                                    |
| TO1.2 | Secrets, variables, environments (ENV1-ENV4), branch protection     | Stay attached to the repository _(to verify: listed by name right after the transfer, TO3)_.                                                                                                                                    |
| TO1.3 | Container packages under `ghcr.io/hr-mes`                           | Stay where they are _(to verify)_. The first runs publish everything again under `ghcr.io/athanor-os` (TO5).                                                                                                                    |
| TO1.4 | GitHub Pages                                                        | `hr-mes.github.io/athanor` becomes `athanor-os.github.io/athanor`, without a redirect _(to verify)_.                                                                                                                            |
| TO1.5 | Keyless signatures and attestations                                 | The workflow identity becomes `https://github.com/athanor-os/athanor/...`. `system/kernel-artifacts.sh` reads it from the run, so the old artifacts no longer match and the first Kernel Build builds again instead of reusing. |
| TO1.6 | The MOK, the Secure Boot and module keys, the image key (SEC1-SEC6) | Unchanged. No key is tied to the owner's name.                                                                                                                                                                                  |

## 2. Steps

| Id  | Who                         | Step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TO2 | maintainer                  | Create the organisation `athanor-os` on the Free plan (github.com/organizations/new). In its settings: require two-factor authentication; under Personal access tokens, allow fine-grained tokens and keep approval required; keep classic tokens allowed while SEC9 is classic.                                                                                                                                                                                                                                                                                                    |
| TO3 | maintainer                  | Repository settings, Danger zone, Transfer, to `athanor-os`. Then check that nothing was lost: `gh secret list --repo athanor-os/athanor`, `gh variable list --repo athanor-os/athanor`, `gh api repos/athanor-os/athanor/environments --jq '.environments[].name'`, `python3 scripts/github-settings/ghsettings.py diff` against `.github/settings/`. Anything missing is made again from [secrets.md](secrets.md) section 1.4. Make again, with `athanor-os` as resource owner, the fine-grained tokens SEC7 (`KERNEL_BUMP_TOKEN`) and SEC8 (`SPECS_UPDATE_TOKEN`), and the runner credential SEC12, then store them as [secrets.md](secrets.md) says. A fine-grained token of the personal account cannot reach a repository of the organisation. SEC9 (`FORGE_PAT`, classic) keeps working while the maintainer is a member with access. |
| TO4 | agent, one pull request     | Replace the owner in content: `git grep -l 'hr-mes'` on the default branch, then `ghcr.io/hr-mes` to `ghcr.io/athanor-os`, `hr-mes/athanor` to `athanor-os/athanor`, `hr-mes.github.io/athanor` to `athanor-os.github.io/athanor`, and the `:-hr-mes` defaults of scripts to `:-athanor-os`. `hr-mes.github.io/athanor-forge`, the dnf repository `athanor-forge.repo` ships, is served by no repository today and is decided separately, not rewritten. Leave the user handles (`@hr-mes`, `@hr-mes-architect`, the `hr-mes` reviewer in `.github/settings/environments.json`), dated records (audits, decision records, reviews) and `scripts/rename.py` as they are. The `REPOSITORY` default of the runner's environment file under `scripts/runner/` changes in the same pull request. |
| TO5 | agent                       | Publish into the new namespace, in the order of the DAG: the builder (`call-build-builder.yml`), the forge packages and tier repositories, Kernel Build, the NVIDIA modules, the system images. The NVIDIA RPM mirror is copied, not rebuilt: the locks name its blobs by digest, so `skopeo copy --all` each tag of `ghcr.io/hr-mes/athanor-nvidia-rpms` to `ghcr.io/athanor-os/athanor-nvidia-rpms`. Every package must be public so machines pull without a login _(to verify: the default visibility of a package an organisation workflow creates)_.                           |
| TO6 | maintainer, on each machine | `sudo bootc switch ghcr.io/athanor-os/athanor-system:latest` (or `-nvidia`, `-nvidia-legacy`), then reboot. A machine that does not switch stays on the last image published under `hr-mes` and gets no update.                                                                                                                                                                                                                                                                                                                                                                     |
| TO7 | maintainer                  | Keep the `hr-mes` account and its packages. Deleting the account would free the name, and with it the `ghcr.io/hr-mes` namespace that a machine which has not switched still follows.                                                                                                                                                                                                                                                                                                                                                                                               |

## 3. Renaming the organisation later

| Id  | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TO8 | GitHub allows renaming an organisation, and repository URLs redirect, but the old name becomes free for anyone to register, together with `ghcr.io/<old name>`, which machines that have not switched still follow. A rename therefore waits until the image policy requires the project key (SEC3, `doc_update_trust.md`) and every machine has switched (TO6). Each rename repeats TO3 to TO6. |
