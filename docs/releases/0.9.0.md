# Athanor 0.9.0 "surface"

Release 0.3 delivered the signed immutable image, the update chain to `:stable` and the
evidence on which a build is promoted. Release 0.9 accepts, on the same evidence, what a person
sees and uses on top of it: the installer path, the greeter, the desktop session, application
installation, and the defaults and confinement that make the system safe to use on real
hardware (ADR-0115).

## What is new

Compared with 0.3, grouped by area. Each item names the specification or decision record that
defines it (`docs/operations/release-1.0.md` rows and section 4.1).

### Desktop shell

- **Bar, dock and launcher** on the cosmic-comp Wayland compositor, with the session's
  idle, wallpaper, workspaces and settings components of COSMIC alongside them
  (`doc_shell.md` SH3, ADR-0103 D13 as amended by ADR-0115).
- **The compositor carries patches 1 and 2** of the cosmic-comp register
  (`doc_compositor.md` CO3, ADR-0103 D14 as amended by ADR-0115). Athanor's own compositor is not part of this release.
- **Visual language and accessibility** ship as release-1.0.md places them in 0.9, without
  the keyboard monitor that answers Orca alone (AX4), which belongs to the own compositor.
  Polkit prompts are cosmic-osd's until Athanor's own polkit agent replaces it in 1.1, and
  until then a screen-reader user cannot read their password field (`doc_accessibility.md`,
  prompts; `release-1.0.md` section 3). The maintainer signed the aesthetic review
  (ST8, VL12) with reservations; the targets it set apply to the surfaces rebuilt on the
  toolkit (#616).

### Session and login

- **Greeter** with a user list, an "Other user" entry and a PAM conversation handled by
  message type, including lockout and expiry (`doc_lock_and_prompts.md` LP19, D7).
- **Session lock and polkit agent** are upstream components packaged in Fedora, confined and
  checked (`doc_lock_and_prompts.md` LP11, row 12). Athanor's own lock and agent come later.
- **Installer path from the ISO to the first session:** Anaconda Users and Timezone pages,
  the Machine Owner Key import with a one-time password shown on screen, and an x86-64-v3
  and UEFI check at ISO start (`doc_platform_experience.md`, `doc_kernel_profile.md` D3, D14).
  The ISO acceptance runs under Secure Boot firmware (#252).

### Security and confinement

- **Least privilege holds:** every shipped service sets `NoNewPrivileges` or a capability
  allow-list, and the PAM rules, including account lockout, are checked
  (`doc_threat_model.md` TM8, ADR-0090).
- **USBGuard** admits devices by class: human interface devices, hubs and the internal
  devices, recorded at first boot, are allowed, and a new external device of another class,
  such as a storage stick, is blocked (`doc_disks.md` DK21, D12). The on-screen
  confirmation of such a device comes with its notice, in a later release.
- **DNS over TLS** is opportunistic in this release. It becomes strict once the
  captive-portal probe ships, which no release is assigned to yet (ADR-0079, D11).
- **`sshd` is off on new installs.** Existing machines that enabled it keep it, and the
  installer's `public` firewall zone loses `ssh` on upgrade (ADR-0089 items 2 and 3,
  ADR-0116, ADR-0119). Where the upgrade replaces the installer's unedited `public` zone, a
  machine reached over ssh on a network in that zone is no longer reachable over ssh; a zone
  the person edited keeps what it has. To avoid the lockout, move that network to the `home`
  zone before the upgrade (`nmcli connection modify <name> connection.zone home`). To recover,
  from the console or from a network in another zone, do the same, or run
  `firewall-cmd --permanent --zone=public --add-service=ssh` and `firewall-cmd --reload`.
- **The `athanor-attestation` crate and the mesh and post-quantum residue are deleted**
  (ADR-0103 D10). The signed release attestation of the update chain is unrelated and stays.

### Updates and the trust chain

- **Update Apply asks for the right authorisation:** `auth_admin` when other sessions are
  open, `allow_active` with one, and a failing inhibitor query refuses the update
  (`doc_update_trust.md` UT6, `doc_threat_model.md` TM9).
- **Recovery and rollback:** text console, GoBack and greenboot (`doc_recovery.md` R1 to R7).

### Software

- **Application installation:** the image ships the pinned Flathub remote and a daily
  update timer, `athanor-flatpak-update.timer` (`doc_software.md` SW15 to SW17). The
  `*.preinstall` reader and the packaged store follow in a later release.
- **Snapshots of your files:** restore from the command line, and a home that cannot be
  snapshotted is reported (ADR-0101, D21).

### Hardware

- **Hardware matrix.** The 0.9 matrix is a recorded run (`docs/operations/hardware-matrix/0.9/`).
  On the laptop all 25 rows pass, among them Secure Boot, suspend and resume, Wi-Fi,
  Bluetooth, audio, camera and the switch to a verified image. On the NVIDIA desktop 19 of 21
  rows pass. The two failures, output hotplug and suspend and resume, are the known limits
  #600 and #604 below. Five rows on each machine, the desktop's two failures among them,
  were recorded on 2026-10-18, on the build each machine then ran, and kept by the
  maintainer's decision, not run again on the candidate.

## Base

Athanor 0.9 ships on Fedora 43 (ADR-0115 item 3). The rebase to a newer Fedora ships as
release 0.10.

## Absent from this release

- **Screenshot and screen share.** Release 0.9 ships without them; they return with the first
  release after steps 4 and 5 of `doc_portal.md` are ready (ADR-0129 item 3).

## Known limits

- **#600:** the shell's surfaces are doubled after an output is disabled and enabled in software.
  Milestone 1.0.
- **#604:** on the NVIDIA desktop the GPU falls off the bus on resume from suspend or on an
  output unplug. Milestone After 1.0.
