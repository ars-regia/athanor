## 2. What the next person must expect

- **The kernel will be rebuilt.** `kernel-local` is an input of `build-inputs.py`. With the
  binding above, the published kernel stops counting as ready until Kernel Build republishes
  the same NVR from a trusted branch, and the orchestrator defers the images meanwhile.
- **A first-run failure is possible and intended.** If Fedora's config lacks one of the two
  lines, `check_delta` stops the build with the line it wanted and the line it found.
- **`verify.py` still fails on the rest of the baseline** (`shipped`, `polkit`, `paths`,
  `docs`); those are older than this branch. Run it before and after any change.

## 3. What is left, in order

1. **Prove what was only tested offline**, on a machine or in CI: the first Kernel Build with
   the new `kernel-local`; a boot matrix run (`boot.sh`); an ISO that boots to the greeter
   with the new command line (this is the goal of `iso-v0`); the recovery acceptance list;
   `athanor-backup` on btrfs; the portal on a real desktop.
2. **Finish the command line**, as `doc_kernel_profile.md` says: move `mem_encrypt=on`,
   `kvm_amd.sev=1`, `kvm_intel.tdx=1` out of the base (capability-specific, never global);
   `preempt=full` (D13); `splash`, `fastboot`, `rootflags=noatime`; and the parameters that
   belong in the build (P4b). Assert the active LSM string once Fedora's config can be read.
3. **Swap on zram (D15)** is not shipped: there is no swap today. It could come from
   `athanor-base-config` with `zram-generator` as a dependency. The profile leaves
   swappiness and writeback to P7, and `doc_local_ai.md` does not plan on it. Needs a decision.
4. **Pin the tier repositories by digest.** They are consumed by a mutable tag. Risk: the
   `buildah` SIGSEGV seen before; it needs the maintainer's CI to test.
5. **The orchestrator's cache and the DAG.** Fix the dirty-node detection (the DAG rebuilds
   every node) and make the workflows portable, as the standing rule asks: logic in scripts,
   YAML as glue, no hard-coded `ghcr.io/hr-mes`. Also: the `inputs` job of `kernel-build.yml`
   still proves reuse with an identity that accepts any workflow or ref, and repeats a
   decision the script now makes; it should ask `kernel-artifacts.sh`. These touch the hot
   files (`Containerfile`, `kernel-bump.yml`, `clean_ghcr.sh`, `azoth/bump.py`,
   `system/nvidia`): check with the maintainer first.
6. **Take the facades out of the tiers**: the five echo specs, `doctor` and
   `athanor-semantic-db`, or make them real. Then decide the fate of the `EXEMPT` crates that
   hold fake cryptography (a placeholder in a security path is a bug by the project's rule).
   Changes to `polkit.rs`, the Gatekeeper and the attestation need the maintainer first.
7. **Correct the documents** listed in section 8 of the project-state review (mark each
   statement outdated or never true, starting with the top-level README).
8. **Shell, stage 2** (`doc_shell.md`): the seven missing bar modules (audio, network,
   Bluetooth, battery, tray, notifications, shield), the notification popup, the notification
   sender binding in `athanor-shelld`, and then the microphone module (indicator, mute, voice
   switch) that `athanor-voice` waits for. The legacy glass theme in `athanor-style` is dead
   code since the kiosk left the workspace.
9. **A design document for build trust**: who may publish, from which runner, how the
   self-hosted runner is trusted (the RPMs are built there), and what an attestation binds.
10. **The local AI packages A0-A5** after the spikes N1-N4 on the maintainer's PC.
