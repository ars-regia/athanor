# Automatic tiling of the own compositor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** athanor-compositor tiles the windows of a workspace when the bar's toggle (F-bar-34) turns tiling on for it, as `doc_own_stack.md` OS12 asks, and the bar reads and sets that state through `athanor_workspace_tiling_v1`, which closes #894 and the tiling half of #739.

**Architecture:** `src/tiling.rs` holds one binary tree per tiled workspace and its layout, generic over what it tiles, so that the layout is tested without a client. The compositor's window paths call it where they already place, remove and carry a window. A layout reaches a window through the existing `Relocate` path: a configure with the tile's size, and the move at the commit that answers it.

**Tech Stack:** Rust; Smithay at the revision pinned in the crate's `Cargo.toml`; `wayland-scanner` for the private protocol.

**Spec:** `docs/architecture/doc_own_stack.md` OS2, OS5 and OS12, revision 2 with its amendments; `docs/architecture/doc_bar.md` BR3. OS12 leaves the layout to this plan, against cosmic-comp's as the reference; a departure is an entry in the feature register, `docs/architecture/shell-features.md` (`doc_compositor.md` CO2).

`C` below is `forge/specs/athanor-compositor/athanor-compositor-1.0.0`; `src/` paths are under it. The reference is cosmic-comp 1.11.0, the version Athanor ships, at its tag `epoch-1.11.0`, cited as `tiling` for `src/shell/layout/tiling/mod.rs`, `floating` for `src/shell/layout/floating/mod.rs`, `layout` for `src/shell/layout/mod.rs`, `workspace` for `src/shell/workspace.rs` and `shell` for `src/shell/mod.rs`. It is GPL-3.0-only: its behaviour is the reference, and its code is read and never copied.

- `panic = "abort"`: no new `unwrap()`, `expect()` or `panic!` outside tests. A tree that does not hold a window has no tile for it: that window is floating.

Decisions recorded in this plan, each to be named in the pull request that implements it:

- **D1, one binary tree per workspace (plan's choice).** Each split has an orientation and the first child's share of it. cosmic-comp keeps groups of any width with sizes in pixels (`tiling`, `Data::Group`), but a new window only ever splits a tile in two; the wider groups come from moves, drops into a group and a minimised tile's return, none of which this plan offers.
- **D2, where a new tile goes (`tiling::map_internal`, `map_to_tree`, `new_group`).** The tile split is that of the window on the workspace focused last, wherever the keyboard is now: a launcher that opens an application leaves the split where it was. Here the tree keeps its windows in the order they were focused (`Tree::focus`, from `State::focus`), as `workspace` keeps a focus stack: the space's order cannot serve, since `park` takes a workspace's windows out of the space and a move to a workspace not shown would find no tile. The tile is split along its longer side, measured after D4's gaps as there, side by side when it is strictly wider than high, in equal halves, and the new window takes the second. An empty workspace gives the window the whole area. The order holds every tile, so one always names the split, and the reference's split of the root, for a focus stack with no tile on it, has no place here. `Tree::insert` puts a new window last in the order, since `place` focuses a window before it has a workspace and `State::focus` cannot note it. A window `place` leaves without the keyboard goes before the last (`Tree::insert_behind`), which holds on any output and whatever has the keyboard; on an empty tree it is `insert`.
- **D3, what an end leaves (`tiling::unmap_internal`).** The sibling takes the parent's place and its whole space.
- **D4, gaps of 8 (`tiling::update_positions`, with the `(0, 8)` of `system/athanor-style/calmo/generated/cosmic/variants.json`).** `Tree::layout` divides the area whole, then takes from each tile 8 logical pixels on a side at the area's edge and 4 on a side it shares, as `update_positions` does: an outer gap of 0, 8 on a free side, 4 on each side of a shared edge. Two tiles of a nested split can so differ by a few pixels, there as here. The area passed in is `State::window_area_on` unchanged: maximise, a drag's clamp and the centring on another output read that function too, and must not lose the gap.
- **D5, what stays floating (`layout::is_dialog`).** A new window with a parent, a modal one, and one whose minimum and maximum size are equal and set. It stands above the tiles. `layout::has_floating_exception` adds about 35 pairs of regular expressions on the application id and the title, from cosmic-comp's `data/tiling-exceptions.ron`, each naming an application. They are not taken (register entry R5): the compositor has no regular expressions, and a list of applications is not a rule of the layout.
- **D6, maximised and full screen.** A maximised window keeps its tile, and a layout skips it (`workspace` keeps it mapped in tiling). A full-screen window keeps its tile as well, and that is a departure (register entry R4): `shell::fullscreen_request` unmaps the tile, the neighbours grow behind the window, and `tiling::remap` splits again on its return. Here the neighbours, hidden on that output, do not change, and the tree needs no state to restore the window: `restore` and `leave_full_screen` end with `tile_layout`, after `back_to`, so that the layout's configure and `Relocate` replace those of the kept geometry. A new tile restores every other maximised window of its workspace, as `shell::map_window` does: `place` restores them after `place_on_workspace` and before the tree takes the new window, whose own request, served before it had a tile, stands, with its tile behind it. A new full-screen window restores them as well, which the reference's `map_fullscreen` does not, since here it holds a tile (R4).
- **D7, the toggle (`workspace::set_tiling`).** Off is the default of a new workspace. On tiles every floating window of the workspace, a dialog included, the topmost first, each by D2: `set_tiling` walks `floating::mapped` with no filter, and D5 applies to new windows only; here a window that hid itself with a null buffer takes no tile (`handlers::shown`), since a hidden tile leaves a hole. A maximised or full-screen window stays so through both, with its tiled states set in the pending state and its kept `before`, in `Maximised` and `FullScreen` both where it has both, changed at once: no configure is sent for it, and the next one `State::focus` sends carries the states, which changes nothing while it stays so. The floating place of such a window is that `before`, not its geometry. The walk leaves the order the reverse of the stack's, so a pass of `Tree::focus` from the bottom of the stack up then makes it the stack's, the topmost last, so that the next tile splits the window used last, and the window with the keyboard goes last. On a workspace not shown the walk takes its parked windows, and `unpark` lays out; off sends those windows D8's configure and rewrites their `parked` place at once. Off returns each window to the place and size it had floating (`floating::unmap` keeps `last_geometry` and `floating::map_internal` reads it), and one that was born tiled is placed by `state::placed`. A workspace that `workspaces_changed` drops is turned off first, so that its windows get D8's configure, and loses the state with its id.
- **D8, tiled states.** A tile gets `tiled_left`, `tiled_right`, `tiled_top` and `tiled_bottom` with its size, so that a client squares its corners. A window that leaves the tree loses them in the configure that gives it its floating size.
- **D9, minimise and workspace moves (register entry R1).** A window that leaves by minimise, or moves to another workspace, leaves the tree; it comes back by D2. cosmic-comp keeps a minimised window's place (`workspace`, `MinimizedWindow::Tiling`).
- **D10, no stacks (register entry R2).** A stack needs the tiling keys and a tab bar drawn by the compositor, and the own compositor draws no decoration.
- **D11, the pointer (register entry R3).** A drag of a tile's title bar swaps it with the tile it is dropped on, and a drop anywhere else puts it back. A client's resize of a tile moves the split nearest that edge, as `tiling::resize_request` does. cosmic-comp also lifts a tile into a preview with drop zones, and takes a press in the gap between tiles.
- **D12, the protocol.** `athanor_workspace_tiling_manager_v1` is a global, privileged (OS4), granted to the bar. Its `get_tiling` takes an `ext_workspace_handle_v1` and makes an `athanor_workspace_tiling_v1`, with a `state` event, `floating` or `tiled`, and a `set_state` request applied at once. The description is MIT, in `system/athanor-compositor-client/protocols/`, and is committed before its first client (OS5).

## Review Focus

1. Every path that ends a window's place on a workspace also leaves its tree: destroy, a null buffer, minimise, a move, a drag to another output (`settle`), an output's removal (`workspaces_changed`). A window enters at `place`, so one that never draws holds no tile. Task 5, `no_end_leaves_a_tile_behind`.
2. A layout never waits on a client: a client that does not answer keeps its old geometry, and the next layout replaces the `Relocate`, as a maximise does today. Task 5.
3. A dialog stays above its parent's tile, and a child never splits a tile. Task 6.
4. The manager is refused to any client but the bar. Task 4.
5. The session without the toggle behaves as today: with tiling off no path changes a window's place. Tasks 3 and 5, and the whole fixture suite.
